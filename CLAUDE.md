# CLAUDE.md — CodeChup Claude Code Academy

This repository is **cc.codechup.com**: a bilingual (EN source, TR translation) static training site that teaches Claude Code from zero to autonomous use. Astro + MDX, Tailwind v4, no server runtime. Public, MIT (D052).

Work is plan-driven and parallel. You are one session among several; everything you need is in the repo.

## Start here (every session, in this order)

1. `STATE.md` — where the project is (generated by the plan CLI; never hand-edit).
2. `plans/README.md` — the plan/claim contract; `plans/ROADMAP.md` for the waves.
3. `DECISIONS.md` — the 100 owner decisions (D001–D100). Cite them as `(Dnnn)`; never re-litigate one.
4. `docs/CURRICULUM.md` — the authoritative lesson map, the lesson template (§3) and the source policy (§4).
5. `research/feature-inventory.md` — the **only** source for "what Claude Code does today". Never write from memory.
6. `docs/design/CANVAS.md` — the approved design; `src/styles/tokens.css` is derived from it.

Then read your own plan file end to end, including its Handoff notes.

## Session protocol

```bash
git fetch origin && git checkout main && git pull --ff-only
node tools/plan/cli.ts next                          # what is claimable right now
node tools/plan/cli.ts claim P11 --owner <session-name>
git checkout -b plan/11-dogfood-claude-setup
git add plans && git commit -m "chore(plans): claim P11" && git push -u origin plan/11-dogfood-claude-setup
git worktree add ../cct-wt-11 plan/11-dogfood-claude-setup   # worktree convention: ../cct-wt-NN
cd ../cct-wt-11 && npm ci                            # each worktree has its own node_modules
# ...work, strictly inside the plan's owned_paths...
node tools/plan/cli.ts check                         # frontmatter + DAG + overlap + STATE.md freshness
gh pr create --base main --title "[P11] Dogfooded .claude/ setup" --body-file .github/PULL_REQUEST_TEMPLATE.md
node tools/plan/cli.ts status P11 review             # then, after the squash merge: status P11 done && state
```

An unpushed claim does not exist — push the branch immediately so other sessions can see it. `/plan-next` wraps these commands.

## Hard rules

- **Evidence (D093).** Every command you say you ran, you actually ran; paste the real output into the PR. Never invent, prettify or "reconstruct" command output, test results or transcripts. If you did not run it, say so.
- **No fabricated transcripts (D070, D099).** Lesson transcripts are captured from real sessions against the lab repo and stored under `content/_shared/transcripts/`; the `<Transcript>` component renders a trimmed copy of a real recording, never a plausible-looking invention.
- **Stay current (D004, D044).** Facts come from `research/feature-inventory.md`. Anything it marks UNVERIFIED goes into your plan's `open_questions`, not into a lesson. Superseded behaviour appears only as a short "Changed" callout.
- **Public-repo hygiene.** This repo is public. Never commit hosting IPs, hostnames, absolute host paths, SSH details, secrets, or anything that names or describes the owner's other private projects or their infrastructure — not in code, docs, plans, comments, tests, fixtures, or as a "for example". Case studies are anonymous or fictional (D026). Deploy targets come from GitHub secrets (`SSH_HOST`, `SSH_USER`, `SSH_KEY`, `DEPLOY_PATH`). Enforced three ways — `scripts/check-public-hygiene.mjs` (lint, pre-commit, CI), the PreToolUse hook `.claude/hooks/guard-hygiene.mjs`, and gitleaks; rule text in `.claude/rules/public-hygiene.md`.
- **Languages (D016, D018).** English is the source; Turkish is a translation with correct diacritics (ç ğ ı İ ö ş ü) and English technical terms kept and explained on first use. Every EN lesson has a TR twin (a `draft: true` stub is acceptable until the TR wave). See `.claude/rules/i18n.md`.
- **Design only through tokens.** Colours come from `src/styles/tokens.css`; no raw hex/rgb literals anywhere else. Mobile-first at 390 px, WCAG 2.2 AA, 44 px touch targets, `prefers-reduced-motion` honoured, no inline `<script>` bodies (CSP). See `.claude/rules/design.md`.
- **Stay inside `owned_paths` (D048).** Files in your plan's `shared_paths` are append-only/minimal-diff. Never edit another plan's files, and never `cd` into another session's worktree.
- **`main` is PR-only.** No direct pushes, squash merges, conventional commits with the plan id (`feat(content): m01-start lesson (P13)`); types `feat|fix|docs|chore|test|refactor|ci|build`.
- **Never commit secrets** — `.env*`, keys, certificates, tokens. Local-only values belong in `.env.local` or `.claude/settings.local.json` (both git-ignored).
- **Never invent an owner decision.** If a plan makes you guess about product, curriculum or design, write the question into the plan's `open_questions` and Handoff notes and take the most conservative reading.

## Commands

```bash
sh scripts/install-hooks.sh    # once per clone/worktree: pre-commit hygiene + pre-push main guard
npm ci && npm run dev          # Astro dev server
npm run typecheck              # astro check
npm run lint                   # eslint + prettier --check + inline-script check
npm run gate                   # content gate: EN/TR parity, frontmatter schema, fenced code
npm test                       # vitest + coverage
npm run build                  # Astro build + Pagefind + dist inline-script check
npx playwright test            # e2e + axe
node scripts/check-public-hygiene.mjs
node tools/plan/cli.ts check && node tools/plan/cli.ts state
```

Project skills: `/plan-next`, `/new-lesson`, `/translate-lesson`, `/verify-sources`.
Project agents: `lesson-researcher`, `lesson-writer`, `translator`, `fact-checker`, `reviewer`.

## Layout

```
content/{en,tr}/<level>/<module>/NN-<slug>.mdx   # lessons (EN source + TR twin)
content/_shared/transcripts/<module>/<slug>/     # real lab transcripts (D099)
src/{layouts,pages,components,lib,styles}        # Astro site; schema in src/content/schema.ts
scripts/                                         # content gate, hygiene/raw-colour checks, smoke
tools/plan/                                      # plan CLI (Node, TypeScript)
plans/ + STATE.md                                # work orders and generated status
docs/{CURRICULUM.md,design/,deploy/}             # curriculum, design canvas, deploy notes
research/                                        # feature inventory, deprecations
.claude/{rules,hooks,skills,agents}/             # this repo's own Claude Code setup (D050, D051)
```

## Model / effort hints

`model_hint` / `effort_hint` in plan frontmatter are advice for the claiming session (D046): `haiku/low` mechanical, `sonnet/medium` infra, CI and translation, `opus/high` lesson authoring and MDX/UI work, `fable/xhigh|max` architecture, design and curriculum. The hint is not a gate — if you find yourself inventing a decision, escalate, and write the question into the plan's Handoff notes.
