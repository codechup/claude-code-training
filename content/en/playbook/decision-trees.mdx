Most of the time the hard part is not writing the `CLAUDE.md` entry, the hook or the agent — it is knowing which of them you should be writing. The trees below encode the distinctions the lessons draw, in the order that decides the answer fastest. Every branch links to the lesson that argues for it, and the diagrams are plain SVG text, so `Ctrl+F` finds any node on this page (D091, D092).

## Which mechanism?

Start here. Three questions separate the six families, and each answer points at a lesson or at one of the finer trees below.

**"Regardless of what Claude decides" is the load-bearing phrase.** `CLAUDE.md`, a rule and a skill are all text the model reads and can be talked out of; a hook is a shell command that runs when its event fires, and a permission rule is evaluated before a tool call is allowed at all. That is why a hard guarantee — never let a force-push through, never write a secret to disk — belongs in a hook or in `permissions.deny`, not in a memory file ([Write a project CLAUDE.md with /init](/en/l1-beginner/m03-memory/claude-md/), [Hook anatomy](/en/l2-intermediate/m07-hooks/hook-anatomy/), [Permission modes and allow/deny rules](/en/l1-beginner/m02-interact/permissions/)).

The reverse is worth saying too: a hook is not a security boundary. Its `if` filter is best-effort, and when Claude Code cannot tell what a Bash string will run, the hook runs anyway — so enforcement that has to hold against a hostile repository is a permission rule plus sandboxing or a container ([Block dangerous commands with a PreToolUse guard](/en/l2-intermediate/m07-hooks/block-dangerous-commands/), [The permission model and the sandbox](/en/l3-advanced/m14-security/permission-model-and-sandbox/)).

**"Reaches a system outside the repo" is not the same as "is external".** If a CLI you already have installed answers the question in one step, use it: `gh pr view 456` in a Bash call is cheaper to run and easier to audit than a GitHub MCP server that costs context in every session. MCP earns its keep when the alternative is you copying data between two windows, or when the task weaves several systems together ([MCP concepts and transports](/en/l3-advanced/m11-mcp/mcp-concepts/), [The GitHub MCP server](/en/l3-advanced/m11-mcp/github-mcp/)).

**"Handed off wholesale" means you can write the brief now and read the result later.** A subagent gets a fresh context window and returns a summary; it does not see your conversation, and you cannot steer it halfway through. That makes it right for breadth — many files, unknown location — and wrong for a single-fact lookup you could do with one `Read` ([The Agent tool and the built-in subagents](/en/l3-advanced/m10-subagents/agent-tool-and-builtins/)).

## Guidance: `CLAUDE.md`, a rule, or a skill?

Once you know it is guidance rather than enforcement, two questions decide where it lives — and both are really questions about context cost.

A skill's body is read when the skill runs; its one-line description is what costs context every turn, which is why a twelve-step release checklist belongs in a skill and not in a memory file ([Skills versus custom commands](/en/l2-intermediate/m06-skills/skills-vs-commands/), [Measuring skills with /skill-doctor](/en/l2-intermediate/m06-skills/skill-doctor/)).

A rule only saves context when it carries `paths:` — an unscoped rule loads at launch exactly like `CLAUDE.md` does. And a scoped rule has one property worth remembering before you rely on it: it lives in message history, so `/compact` summarises it away and it returns only when Claude next reads a matching file. Anything that must survive compaction stays unscoped or in the project-root `CLAUDE.md` ([Path-scoped rules with .claude/rules/](/en/l1-beginner/m03-memory/rules/), [The memory hierarchy, @imports and claudeMdExcludes](/en/l1-beginner/m03-memory/hierarchy-imports/), [Context engineering](/en/l4-master/m21-scale/context-engineering/)).

## Delegation: subagent, fork, or an isolated worktree?

All three are "hand it to another context". They differ in what the worker starts with and where its edits land.

Forking is the expensive branch on purpose: it copies your whole conversation into the subagent, which is exactly the context cost delegation usually exists to avoid. Take it only when the side task genuinely depends on what was just discussed. Worktree isolation buys you a separate checkout — and hands you a cold environment with no `node_modules` and no `.env`, branched from the default branch unless you set `worktree.baseRef` to `"head"` ([Fork, background and worktree isolation](/en/l3-advanced/m10-subagents/fork-background-worktree/)).

Two further distinctions sit just outside this tree. A **custom agent** in `.claude/agents/` is the right shape when the same role recurs and differs mechanically — different tools, model or permission mode — from `general-purpose`; if the only difference is a longer prompt, you want a skill ([Custom agents in .claude/agents/](/en/l3-advanced/m10-subagents/custom-agents/)). An **agent team** is the right shape only when the workers genuinely work in parallel on disjoint files and discussion between them buys something; teammates in plan mode run at roughly seven times a standard session ([Agent teams and cross-session messaging](/en/l4-master/m16-orchestration/agent-teams-messaging/)).

## Model and effort

The most common mistake here is reaching for the dial before checking whether the task was well posed.

Whatever the tree says, decide once and at the top of the session: on most models a mid-task change of model or effort throws away the prompt cache and the next request re-reads the whole conversation at full price. If you want to compare, compare across two sessions from the same starting state ([Choosing a model](/en/l2-intermediate/m05-models-effort/choosing-a-model/), [Effort levels](/en/l2-intermediate/m05-models-effort/effort-levels/), [Prompt caching](/en/l4-master/m21-scale/prompt-caching/)).

`max` is documented as prone to overthinking with diminishing returns, and `ultrathink` is the one-turn escalation that leaves your session setting and cache intact. Fast mode is the latency dial, not the quality one, and it is the wrong choice for CI and long autonomous runs ([Fast mode](/en/l2-intermediate/m05-models-effort/fast-mode/), [ultracode](/en/l4-master/m16-orchestration/ultracode/)).

## The one-line version

| You want…                             | Reach for                            | Lesson                                                                            |
| ------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------- |
| A fact every session should know      | `CLAUDE.md`                          | [claude-md](/en/l1-beginner/m03-memory/claude-md/)                                |

| A procedure with steps                | a skill                              | [skills-vs-commands](/en/l2-intermediate/m06-skills/skills-vs-commands/)          |
| Something to happen at a fixed moment | a hook                               | [hook-anatomy](/en/l2-intermediate/m07-hooks/hook-anatomy/)                       |
| Something never to happen             | `permissions.deny` (plus sandboxing) | [permissions](/en/l1-beginner/m02-interact/permissions/)                          |
| A recurring role with its own tools   | a custom agent                       | [custom-agents](/en/l3-advanced/m10-subagents/custom-agents/)                     |
