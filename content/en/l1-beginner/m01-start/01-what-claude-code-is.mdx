## Objectives & prerequisites

By the end of this lesson you can:

- Say in one sentence what Claude Code is, and what makes it different from pasting code into a chat window.
- Describe the agentic loop — gather context, take action, verify results — and point at which part of a real session is doing which.
- Name the categories of built-in tools Claude reaches for, and say which one you would expect it to use for a given request.
- List the surfaces Claude Code runs on: terminal, IDE extensions, the desktop app, and the web.
- Prove your own install is healthy with `claude --version` and `claude doctor`, and get an answer out of a first, read-only session.

**Prerequisites.** A terminal you are comfortable opening, and a Claude subscription (Pro, Max, Team or Enterprise) or an Anthropic Console account — the free Claude.ai plan does not include Claude Code. You do not need Claude Code installed yet: the lab below covers checking or getting an install.

<WhenNotToUse>
  Claude Code is an agent that reads, edits and runs things in a real working directory. Reach for
  something else when you only want a paragraph of prose or a snippet with no project attached (a
  plain chat window is faster), when the work is a one-line change you can type quicker than you can
  describe, when you are not allowed to let a tool read the repository you are sitting in, or when
  the task has no way to be verified — an agent's value comes from running the check afterwards, and
  a task with no check is a task where you cannot tell whether it worked.
</WhenNotToUse>

## Concept

### What it is

Claude Code is an **agentic coding tool that reads your codebase, edits files, runs commands, and integrates with your development tools**. You point it at a project directory and talk to it in plain language; it decides which files to open, which commands to run, and what to change.

The difference from a chat window is not the model — it is the harness around it. Claude Code provides the tools, the context management and the execution environment that turn a language model into something that can act on your project. The docs call it the **agentic harness**.

### The agentic loop

Given a task, Claude works through three phases that blend into each other:

1. **Gather context** — search the project, read the files that look relevant, run a command to see the current state.
2. **Take action** — edit files, create them, run a build or a script.
3. **Verify results** — run the tests, re-read the file, check the output actually changed.

The loop repeats until the task is done, and each step's result informs the next one. A question about your codebase might only ever gather context; a bug fix cycles through all three several times. You are inside the loop too: press `Esc` to stop Claude mid-action, or type a correction and press `Enter` to steer without stopping the running tool.

Every lesson on this site carries one worked example prompt. Here is this lesson's — a task shaped so the loop has something to verify against:

```text
The checkout flow is broken for users with expired cards.
The relevant code is in src/payments/. Can you investigate and fix it?
```

Notice what it does _not_ say: which files to read, which commands to run, or what the fix should look like. That is the point — you delegate the goal and the constraints, and Claude works out the steps.

### Where it runs

The loop, the tools and the capabilities are the same everywhere; what changes is where your code executes and how you look at it.

| Surface             | What it is                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| Terminal            | The full-featured CLI. Run `claude` in a project directory.                                      |
| VS Code / JetBrains | IDE extensions: inline diffs, `@`-mentions, plan review, selection context.                      |
| Desktop app         | A standalone app — visual diffs, several sessions side by side, scheduled tasks, cloud sessions. |
| Web                 | `claude.ai/code` in a browser, plus the Claude mobile app. No local setup.                       |

Beyond those, Claude Code also reaches into CI/CD (GitHub Actions, GitLab), Slack, and the browser via Chrome. Each surface talks to the same engine, so your project's `CLAUDE.md`, settings and MCP servers work across all of them.

Code executes in one of three environments: **local** (your machine — the default), **cloud** (Anthropic-managed VMs, or self-hosted ones your organisation runs), or **Remote Control** (execution stays on your machine while you drive it from a browser).

### The built-in tools

Tools are what make it agentic — without them Claude can only reply with text. The built-in set falls into five categories:

| Category          | What Claude can do                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------- |
| File operations   | Read files, edit code, create new files, rename and reorganise                                       |
| Search            | Find files by pattern, search content with regex, explore codebases                                  |
| Execution         | Run shell commands, start servers, run tests, use git                                                |
| Web               | Search the web, fetch documentation, look up error messages                                          |
| Code intelligence | See type errors after edits, jump to definitions, find references (needs a code-intelligence plugin) |

In practice the names you will see scroll past in a session are `Read`, `Edit`, `Write`, `Glob`, `Grep`, `Bash` (or `PowerShell` on native Windows), `WebFetch` and `WebSearch`. There are more — `Agent` for spawning a subagent, `Skill`, the `Task*` checklist tools (`TaskCreate`, `TaskUpdate`, …; the older `TodoWrite` is disabled by default), `Monitor` and others — and the full list lives in the tools reference. Claude picks them itself, based on your prompt and on what the previous tool call returned.

### Models at a glance

Claude Code runs on several Claude models with different trade-offs. Sonnet handles most coding work; Opus gives stronger reasoning for hard architectural calls. Switch mid-session with `/model`, or start with `claude --model <name>`. Choosing deliberately between them — and choosing an effort level — is a level 2 topic; for now, the default is a good default.

Two things in that recording are worth stopping on.

The third transcript is a real capture, and the machine that produced it has global Claude Code preferences asking for Turkish answers — so the model answered in Turkish and said so in its first line, even though the prompt asked for English. That is not a mistake in the recording; it is a genuine and very useful lesson. Your standing preferences and memory files shape every session, including ones you thought were stateless.

The Windows (WSL) tab reuses the Linux panel on purpose: inside a WSL distribution you run the Linux installer and launch `claude` from the WSL terminal, not from PowerShell. On native Windows, installing Git for Windows is optional but recommended — with it Claude Code uses Git Bash for the `Bash` tool; without it, it uses the `PowerShell` tool instead. macOS Homebrew installs do not auto-update, so `brew upgrade claude-code` is on you; native installs update themselves in the background.

## Anti-patterns

**Treating it like a chat window.** Pasting a file's contents into the prompt and asking for a rewrite throws away the whole point: Claude Code reads your project files as needed, and you do not have to add context manually. _Fix:_ name the file or the area and let it read.

**Asking for a change you have no way to check.** The loop's third phase is verification. A task with no test, no build and no observable output leaves both of you guessing. _Fix:_ say what "done" looks like — a passing test, a command that exits 0, a specific line that should change.

**Over-specifying the steps.** Dictating which files to open and which commands to run turns an agent into a slow macro. The docs' own advice is to delegate rather than dictate: give context and direction, and let Claude work out the details. _Fix:_ state the goal, the constraints and the evidence you want back.

**Assuming a session starts blank.** A session loads your `CLAUDE.md`, your auto-memory and your settings before it reads your first word — as the lab's third transcript shows, that can change the language of the answer. _Fix:_ when a result surprises you, check what is loaded (`/context`) before blaming the prompt.

**Trusting a claim without the output.** "The tests pass" is not evidence; the test runner's output is. _Fix:_ ask for the command and its output, and read it.
