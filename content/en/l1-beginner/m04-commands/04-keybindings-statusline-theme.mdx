## Objectives & prerequisites

By the end of this lesson you can:

- Open and edit `~/.claude/keybindings.json`, read its `bindings` / `context` shape, write a chord, and unbind a key.
- Name the shortcuts you will actually use daily, and say which six can never be rebound and why.
- Configure a status line with `/statusline` or by hand, and read the JSON Claude Code pipes to your script on stdin.
- Pick a theme, write a custom one in `~/.claude/themes/`, and switch to the fullscreen renderer.
- Choose an output style, and say what an output style changes that `CLAUDE.md` does not.

**Prerequisites.** Lesson 01 of this module for the commands involved (`/keybindings`, `/statusline`, `/theme`, `/tui`, `/config`), and a terminal you can edit a JSON file from.

<WhenNotToUse>
  This is the most optional lesson in the module. Nothing here makes Claude better at your code — it
  makes the interface fit your hands. Skip the customisation entirely if you are new: the defaults
  are good, and a rebound key you half-remember is worse than the default you never think about. Do
  not put slow work in a status-line script — it runs on every assistant message and a slow one
  makes the whole UI feel laggy. And do not reach for a custom output style when what you actually
  want is for Claude to know your project's conventions; that is what `CLAUDE.md` is for.
</WhenNotToUse>

## Concept

### Keyboard shortcuts

Run `/keybindings` to create or open your configuration file at `~/.claude/keybindings.json`. Changes are detected and applied without restarting Claude Code.

The file is a list of blocks, each scoped to a **context** — the part of the UI the binding applies in. Contexts include `Global`, `Chat`, `Autocomplete`, `Settings`, `Confirmation`, `Tabs`, `Help`, `Transcript`, `HistorySearch`, `Task`, `ThemePicker`, `Attachments`, `Footer`, `MessageSelector`, `DiffDialog`, `DiffPanel`, `ModelPicker`, `Select`, `Plugin` and `Scroll`. Actions are named `namespace:action`.

<CodeBlock title="~/.claude/keybindings.json">

```json
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "$docs": "https://code.claude.com/docs/en/keybindings",
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+e": "chat:externalEditor",
        "ctrl+u": null
      }
    }
  ]
}
```

</CodeBlock>

A `null` value unbinds the key. Modifiers join with `+`, and the aliases are worth knowing: `ctrl`/`control`; `shift`; `alt`/`opt`/`option`/`meta` (Alt on Windows and Linux, Option on macOS); `cmd`/`command`/`super`/`win`. The `cmd` group is only detected in terminals that report the Super modifier, so use `ctrl` or `meta` for bindings you want to work everywhere. **Chords are sequences separated by spaces**: `"ctrl+k ctrl+s"` means press Ctrl+K, release, then Ctrl+S.

The defaults you will meet first:

| Shortcut      | Action                              | What it does                                          |
| ------------- | ----------------------------------- | ----------------------------------------------------- |
| `Enter`       | `chat:submit`                       | Send the message                                      |
| `Ctrl+J`      | `chat:newline`                      | Insert a newline without submitting                   |
| `Escape`      | `chat:cancel`                       | Cancel the current input                              |
| `Shift+Tab`   | `chat:cycleMode`                    | Cycle permission modes                                |
| `Ctrl+O`      | `app:toggleTranscript`              | Show the full transcript                              |
| `Ctrl+R`      | `history:search`                    | Search your prompt history                            |
| `Up` / `Down` | `history:previous` / `history:next` | Step through prompt history                           |
| `Ctrl+G`      | `chat:externalEditor`               | Edit the prompt in your editor (also `Ctrl+X Ctrl+E`) |
| `Meta+P`      | `chat:modelPicker`                  | Open the model picker                                 |

Six keys are **reserved and cannot be rebound**, because the terminal itself decides what they mean: `Ctrl+C` (interrupt), `Ctrl+D` (exit — press twice within 800 ms to confirm), `Ctrl+M` (always arrives as Enter), `Ctrl+[` (always arrives as Escape), `Ctrl+I` (always arrives as Tab), and `Ctrl+H` (the ASCII backspace byte). Caps Lock is never delivered to terminal applications at all.

Two platform notes. On Windows without VT mode — Node below 24.2.0 or 22.17.0, Bun below 1.2.23 — `Shift+Tab` falls back to `Meta+M`. And image paste is `Ctrl+V` everywhere except Windows and WSL, where it is `Alt+V`.

Watch out for terminal multiplexers stealing your key: `Ctrl+B` is the tmux prefix, `Ctrl+A` is GNU screen's, and `Ctrl+Z` suspends the process on Unix.

If a binding does nothing, Claude Code has probably rejected it. It warns on parse errors, invalid context names, unknown action names, reserved-shortcut conflicts and duplicates — and writes those warnings to the debug log, so run with `--debug` to see them.

### Multiline input, which is mostly a terminal problem

Two ways work in **every** terminal with no setup: `Ctrl+J`, or type `\` then press `Enter`. `Shift+Enter` is the comfortable one, and whether it works depends on your terminal:

| Terminal                                                                | What to do                                    |
| ----------------------------------------------------------------------- | --------------------------------------------- |
| Ghostty, Kitty, iTerm2, WezTerm, Warp, Apple Terminal, Windows Terminal | Works without setup                           |
| VS Code, Cursor, Devin Desktop, Alacritty, Zed                          | Run `/terminal-setup` once                    |
| gnome-terminal, JetBrains IDEs such as PyCharm and Android Studio       | Not available; use `Ctrl+J` or `\` then Enter |

`/terminal-setup` writes the keybinding into the terminal's own configuration file. In VS Code, Cursor and Devin Desktop it also turns off `terminal.integrated.gpuAcceleration` to prevent garbled text, and adjusts `terminal.integrated.mouseWheelScrollSensitivity` for smoother fullscreen scrolling. In Apple Terminal it enables Option as Meta and turns off the audible bell instead; in iTerm2 it enables clipboard access so `/copy` works. Run it in the host terminal, not inside tmux or screen.

### The status line

`/statusline` accepts natural-language instructions describing what you want displayed. Claude Code generates a script in `~/.claude/` and updates your settings for you.

<CodeBlock title="configure it by describing it">

```text
/statusline show model name and context percentage with a progress bar
```

</CodeBlock>

The settings it writes look like this:

<CodeBlock title="settings.json">

```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 2
  }
}
```

</CodeBlock>

`command` is a script path or an inline shell command, and it runs in a shell. `padding` adds horizontal spacing in characters and defaults to `0`. Two optional siblings: `refreshInterval` re-runs the command every N seconds (minimum `1`; leave it unset to run only on events), and `hideVimModeIndicator` suppresses the built-in `-- INSERT --` text when your script renders `vim.mode` itself.

The interesting part is what your script gets. Claude Code pipes it a JSON object on **stdin** with, among others:

| Field                                   | What it holds                                                       |
| --------------------------------------- | ------------------------------------------------------------------- |
| `model.display_name`, `model.id`        | The model in use                                                    |
| `workspace.current_dir`, `.project_dir` | Where the session is                                                |
| `context_window.used_percentage`        | How full the window is (input tokens only — not output)             |
| `cost.total_cost_usd`                   | Session spend; resets to $0 when `/clear` starts a new conversation |
| `session_id`, `session_name`, `version` | Session identity and the Claude Code version                        |
| `effort.level`, `thinking.enabled`      | Current effort and thinking state                                   |
| `vim.mode`, `output_style.name`         | Editor mode, active output style                                    |
| `pr.number`, `worktree.branch`          | The PR and worktree this session is tied to                         |

Several fields may be **absent** rather than null — `session_name`, `effort`, `vim`, `agent`, `pr`, `worktree`, `rate_limits` among them — so write defaults into your `jq` expressions.

<CodeBlock title="~/.claude/statusline.sh">

```bash
#!/bin/bash
input=$(cat)
MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
PCT=$(echo "$input" | jq -r '.context_window.used_percentage // 0' | cut -d. -f1)
echo "[$MODEL] ${DIR##*/} | ${PCT}% context"
```

</CodeBlock>

Every `echo` is a separate row, and ANSI colour codes work. The script runs at session start and again on each new assistant message, after `/compact`, on a permission-mode or vim-mode change, and on a `refreshInterval` tick — debounced at 300 ms, and cancelled if a new update arrives while it is still running. That is the reason to keep it fast. It runs locally and costs no API tokens.

A Windows note that costs people an hour: status-line commands run through Git Bash when Git Bash is installed, and Git Bash eats unquoted backslashes, so a path like `C:\Users\you\script.mjs` arrives with its separators removed and fails silently. **Write paths with forward slashes.**

To remove a status line, run `/statusline` and ask it to: `/statusline clear` works.

### Themes and the renderer

Run `/theme`, or use the picker in `/config`. The `auto` option detects your terminal's light or dark background, so the theme follows OS appearance changes whenever your terminal does. The list includes light and dark variants, colourblind-accessible (daltonized) themes, ANSI themes that use your terminal's own palette, and any custom themes you have written.

A custom theme is a JSON file in `~/.claude/themes/`. The filename without `.json` is the theme's slug, and selecting it stores `custom:<slug>` as your preference. Three optional fields: `name`, `base` (one of `dark`, `light`, `dark-daltonized`, `light-daltonized`, `dark-ansi`, `light-ansi`; defaults to `dark`), and `overrides`.

<CodeBlock title="~/.claude/themes/dracula.json">

```json
{
  "name": "Dracula",
  "base": "dark",
  "overrides": {
    "claude": "#bd93f9",
    "error": "#ff5555",
    "success": "#50fa7b"
  }
}
```

</CodeBlock>

Colour values may be `#rrggbb`, `#rgb`, `rgb(r,g,b)`, `ansi256(n)` or `ansi:<name>`. Unknown tokens and invalid values are ignored, so a typo cannot break rendering. The folder is watched and reloads live — but if `~/.claude/themes/` did not exist when Claude Code started, restart once after creating your first file.

For the **renderer**, run `/tui fullscreen`. Claude Code saves the `tui` setting and relaunches with your conversation intact, so future sessions start in fullscreen — the flicker-free alt-screen renderer. `/tui default` switches back to the classic renderer, and `/tui` with no argument prints which one is active. Fullscreen is what makes `/focus` and `/scroll-speed` available. In screen-reader mode fullscreen does not apply, and `/tui fullscreen` prints an explanation instead of switching.

### Output styles

An output style changes **how Claude responds, not what Claude knows**. It modifies the system prompt to set role, tone and output format. Reach for one when you keep re-prompting for the same voice every turn.

Besides the **Default** style, four are built in:

| Style           | What it does                                                                                |
| --------------- | ------------------------------------------------------------------------------------------- |
| **Proactive**   | Executes immediately, makes reasonable assumptions instead of pausing for routine decisions |
| **Concise**     | Leads with the result, skips preamble, keeps responses short — while doing the same work    |
| **Explanatory** | Adds educational "Insights" while completing tasks                                          |
| **Learning**    | Adds `TODO(human)` markers and asks you to contribute small pieces of code yourself         |

Pick one in `/config` under **Output style**, which saves your choice to `.claude/settings.local.json`, or set `outputStyle` in a settings file directly. Output style is part of the system prompt, which Claude Code reads once at session start — **changes take effect after `/clear` or a new session**, not immediately.

A custom style is a Markdown file in `~/.claude/output-styles`, `.claude/output-styles`, or the managed-settings equivalent. The filename becomes the style name unless frontmatter sets `name`. The field that decides everything is `keep-coding-instructions`: leave it out (it defaults to `false`) and Claude Code's built-in software-engineering instructions are dropped, which is right for a writing assistant and wrong for anything still writing code.

<CodeBlock title=".claude/output-styles/diagrams-first.md">

```markdown
---
name: Diagrams first
description: Lead every explanation with a diagram
keep-coding-instructions: true
---

When explaining code, architecture, or data flow, start with a Mermaid diagram showing the
structure, then explain in prose.
```

</CodeBlock>

Output styles apply to the main conversation only — a subagent runs its own system prompt, so styles do not change how subagents respond. A fork is the exception, because it inherits the parent's full system prompt.

Here is this lesson's example prompt, which is how most people should configure a status line:

```text
/statusline show the model, the git branch, and how full the context window is,
and keep it to one line
```

## Anti-patterns

**Rebinding `Ctrl+C` or `Ctrl+D`.** They are reserved: the terminal decides what those bytes mean before Claude Code sees them. _Fix:_ pick a key that is not on the reserved list — `Ctrl+M`, `Ctrl+[`, `Ctrl+I` and `Ctrl+H` are out too.

**Assuming a silent binding is a Claude Code bug.** An unknown action name or an invalid context is rejected, and the warning goes to the debug log, not the screen. _Fix:_ start with `--debug` and read the log before rewriting the file again.

**Putting a network call or a slow git command in the status line.** It runs on every assistant message; a slow script makes the whole UI feel laggy, and Claude Code cancels an in-flight one when a new update arrives. _Fix:_ keep it to local, fast reads, and use `session_id` as a cache key if you need to memoise something.

**Writing a Windows path with backslashes in `statusLine.command`.** Git Bash strips them and the command fails with no visible error. _Fix:_ forward slashes, always.

**Expecting an output style change to take effect mid-conversation.** It is part of the system prompt, read once at session start. _Fix:_ `/clear`, or start a new session.

**Writing a custom output style without `keep-coding-instructions: true` while still coding.** You silently drop Claude Code's built-in engineering instructions — how to scope changes, write comments and verify work. _Fix:_ set it to `true` unless Claude genuinely is not doing software engineering.

**Reaching for an output style to teach Claude your project.** Styles change voice, not knowledge. _Fix:_ project conventions and codebase context belong in `CLAUDE.md`.

<Callout variant="changed">
  The `keybindingFlavor` setting is ignored and no longer appears in the keybindings reference —
  verified against `keybindings.md` for Claude Code 2.1.263. Word-editing keys are always
  Bash-style: `Ctrl+W` deletes back to the previous whitespace, `Alt+B` and `Alt+F` move a word,
  `Alt+D` deletes to the end of a word, and `Ctrl+Y` pastes back whatever a word or line shortcut
  last deleted — all of them documented in `interactive-mode.md`, and all of them needing
  Option-as-Meta on macOS.
</Callout>

<Callout variant="changed">
  There is no `/output-style` command any more: it was deprecated in v2.1.73 and removed in v2.1.91.
  Pick a style in `/config` under **Output style**, or set the `outputStyle` field in a settings
  file. Likewise, the renderer is switched with `/tui fullscreen`, not a `/fullscreen` command.
</Callout>
