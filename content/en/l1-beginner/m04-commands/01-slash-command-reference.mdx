## Objectives & prerequisites

By the end of this lesson you can:

- Say what a slash command is, where it is recognised in a message, and what happens to the text after the command name.
- Reach for the right command at the right moment: first session in a repo, mid-task, running work in parallel, before you ship, between sessions, and when something is wrong.
- Read the full built-in command table and find a command by what you want to do rather than by its name.
- Tell a **built-in** command from a bundled **Skill** and a bundled **Workflow**, and say why the distinction matters.
- Explain why a command you read about might not appear in your own `/` menu, and how to find the hidden ones.

**Prerequisites.** A working Claude Code install you can start a session with (`m01-start`), and enough of `m02-interact` to know what a permission mode and a context window are. Nothing in this lesson edits code.

<WhenNotToUse>
  Slash commands are for controlling Claude Code, not for doing your work. Do not reach for one when
  a plain sentence would do — asking "review the changes in src/payments and tell me what looks
  wrong" is usually better than hunting for a command that almost fits. Do not memorise this table:
  it is a reference you come back to, and `/help` plus typing `/` and a few letters finds a command
  faster than recall does. And do not treat it as a stable API — commands are added, renamed and
  removed between versions, so a script that depends on one is more fragile than the equivalent CLI
  flag, which the next lesson covers.
</WhenNotToUse>

## Concept

### What a slash command is

A command controls Claude Code from inside a session: switch models, manage permissions, clear context, run a workflow. Type `/` to see the commands available to you, or type `/` followed by letters to filter the list.

Two rules about where a command may appear:

- **A command is only recognised at the start of your message.** Text that follows the command name becomes its arguments.
- **Skills are the exception.** As of v2.1.199, a skill invocation followed by more skills — `/skill-a /skill-b do XYZ` — loads every skill named at the start and passes the trailing text to each as arguments. Up to six skills can be chained.

If you send a command while Claude is responding, Claude Code queues it and runs it after the current turn finishes. Some commands run immediately without interrupting the response — `/status`, `/tasks` and `/usage` among them. In fullscreen rendering, dialog commands such as `/theme` and `/help` also open immediately; before v2.1.234 those dialogs waited for the turn to end.

### Three kinds of entry in the table

Most entries are **built-in** commands whose behaviour is coded into the CLI. Two kinds are marked differently, and the difference is real:

| Kind         | What it is                                                                             | Consequence                                                                    |
| ------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Built-in     | Behaviour coded into the CLI                                                           | Deterministic; does the same thing every time                                  |
| **Skill**    | A bundled skill — a prompt handed to Claude, exactly like the skills you write         | Claude interprets it; you can write your own the same way                      |
| **Workflow** | A bundled dynamic workflow that fans work out across many subagents, in the background | Long-running; you watch it with `/workflows` rather than waiting at the prompt |

Two of them are invoke-only: `/verify` runs only when you invoke it (before v2.1.215 Claude could also run it on its own), and `/deep-research` likewise (before v2.1.218 Claude could start it on its own).

### The commands you actually reach for, by moment

The full table below is a lookup. This is the part worth reading once, because it maps a moment in your day to a command.

**First session in a repo.** Run `/init` to generate a starter `CLAUDE.md`, then `/memory` to refine it. Use `/mcp` to set up any servers the project needs, ask Claude to create any subagents you want, and run `/permissions` to set your approval rules.

**During a task.** `/plan` switches into plan mode before a large change. `/model` and `/effort` adjust which model you are using and how much reasoning it applies. When the conversation gets long, `/context` shows what is filling the window and `/compact` summarises it to free space. Use `/btw` for a side question that should not add to the conversation history.

**Run work in parallel.** `/tasks` lists the current session's background work, including subagents that have finished. `/background` detaches the whole session to keep running as a background agent and frees your terminal. For a large change that spans the codebase, `/batch` decomposes it into independent units and runs each in its own worktree.

**Before you ship.** `/diff` shows what changed. `/code-review` checks the current diff for correctness bugs and cleanups and can apply the findings with `--fix`; pass a PR number, such as `/code-review high 1234`, to review a pull request instead. `/review` is an alias. `/code-review ultra` runs a multi-agent review in the cloud. `/security-review` checks the diff for security vulnerabilities.

**Between sessions.** `/clear` starts fresh on a new task while keeping project memory. `/resume` returns to an earlier conversation, `/branch` branches the current one to try a different direction, and `/fork` copies it into a new background session. `/teleport` pulls a web session into this terminal, and `/remote-control` lets you continue this local session from another device.

**When something is wrong.** `/rewind` rolls code and conversation back to a checkpoint, or summarises part of the conversation. `/doctor` runs a setup checkup that diagnoses installation and configuration issues and can fix them, `/debug` diagnoses runtime issues, and `/feedback` reports a bug with session context attached.

Here is this lesson's example prompt — the shape that makes the difference between reaching for a command and just asking:

```text
Before I open this PR: show me what changed, then check the diff for
correctness bugs. Do not fix anything yet — list what you find.
```

That is `/diff` followed by `/code-review`, and saying it in one sentence is often faster than typing both.

### Why your `/` menu is shorter than this table

Not every command appears for every user. Availability depends on your platform, plan and environment: `/desktop` only shows on macOS and x64 Windows when signed in with a Claude subscription, and `/upgrade` does not show on Enterprise plans. Four behaviours are worth knowing:

- **Highlighting.** Claude Code highlights the top suggestion only when the letters after the `/` match a command's name or alias, from the start of the name or from a word within it, ignoring `:`, `_` and `-`. Typing `/adddir` highlights `/add-dir`; typing `/new` highlights `/clear` through its alias. `Enter` runs the highlighted suggestion.
- **After a typo.** Nothing is highlighted. Close matches stay listed and you can pick one with `Tab` or the arrow keys, but `Enter` submits your text as typed and reports `Unknown command`.
- **Commands not available to you.** They are left out of the menu entirely. When nothing matches, you get `No commands match "/name"`.
- **Hidden commands.** A few available commands — `/heapdump`, `/rate-limit-options`, `/setup-bedrock`, `/setup-vertex` — are kept out of the menu by design. A partial name never brings one into the menu; type the full name and it runs.

MCP servers can also expose prompts that appear as commands, so a project with servers configured will show entries this table does not list.

## Anti-patterns

**Typing a command mid-sentence.** `please /compact this` does nothing — a command is only recognised at the start of a message. _Fix:_ send the command on its own, then the sentence.

**Assuming a queued command ran immediately.** Send `/model opus` while Claude is mid-answer and, for most commands, it waits for the turn to finish. _Fix:_ if the change matters for the current turn, stop the turn with `Esc` first; check `/status` to confirm what is actually in effect.

**Scripting around a slash command.** Commands live inside an interactive session and change between versions. _Fix:_ for anything scripted, use the CLI flags in the next lesson — `claude -p`, `--model`, `--permission-mode` — which are the stable surface.

**Reading a bundled Skill as a built-in.** `/code-review`, `/simplify` and `/doctor` are prompts handed to Claude, not fixed procedures. Their output varies with the model and the diff. _Fix:_ treat their findings as a review to read, not a verdict to trust; and remember you can write your own skills the same way.

**Guessing at a command's arguments.** Most commands do something sensible with no argument — `/model` opens a picker, `/resume` opens the session picker, `/statusline` auto-configures. _Fix:_ run it bare first and read what it offers.

**Confusing `/fork`, `/branch` and `/subtask`.** They all copy a conversation, and they differ in where you end up. _Fix:_ `/branch` switches you into the copy; `/fork` runs the copy as a separate background session while you stay here; `/subtask` hands work to a subagent whose result comes back into this conversation. Lesson 03 covers the first two properly.

<Callout variant="changed">
  Four commands 2025-era tutorials still show are gone. `/pr-comments` was removed in v2.1.91 — ask
  Claude to view pull request comments instead. `/vim` was removed in v2.1.92 — toggle editing modes
  from `/config` → Editor mode. `/ultraplan` was removed — use plan mode. And the standalone
  `/output-style` command was deprecated in v2.1.73 and removed in v2.1.91 — pick a style in
  `/config` or set the `outputStyle` setting directly.
</Callout>

<Callout variant="changed">
  `/btw` no longer needs a question. Run it bare and the overlay reopens on your most recent side

</Callout>
