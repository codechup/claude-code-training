## Objectives & prerequisites

By the end of this lesson you can:

- Say what a session is, where its transcript lives, and how long it is kept.
- Get back into a conversation four ways — `claude --continue`, `claude --resume <id>`, `claude --resume <name>`, `/resume` from inside a session — and say which one skips which sessions.
- Name a session at launch or mid-session so it is findable later, and navigate the session picker with its keyboard shortcuts.
- Explain what a resumed session restores and what it does not, including the permission-mode rules.
- Choose correctly between `/branch`, `/fork` and `--fork-session` when you want a second direction.

**Prerequisites.** Lesson 02 of this module — you need to be comfortable reading the `session_id` out of a `claude -p --output-format json` envelope. The lab runs against the lab repository at `lesson/m04-03-start`.

<WhenNotToUse>
  Resuming is not always the right move. A long session carries its whole history into every
  request, so when the next task is genuinely a different task, `/clear` and a fresh start is
  cheaper and sharper than resuming a conversation full of irrelevant context. Branching is not
  version control either — it copies a conversation, not your files, so two branches editing the
  same repository will still collide on disk. And do not use `--resume` as a substitute for writing
  things down: a session is deleted after 30 days by default, so anything that has to survive
  belongs in `CLAUDE.md`, a commit message or an issue.
</WhenNotToUse>

## Concept

### What a session is

A session is a saved conversation tied to a project directory. Claude Code writes it continuously to a local transcript as you work, so you can return to one after exiting or after `/clear`.

Transcripts are JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is your working directory path with non-alphanumeric characters replaced by `-`. The entry format is internal and changes between versions, so do not parse those files yourself — use `/export`, or the scripted interfaces below. Retention is 30 days by default, changed with the `cleanupPeriodDays` setting.

The desktop app, Claude Code on the web and the VS Code extension each keep their own session history. This lesson is about the CLI.

### Getting back in

| Command                     | What it does                                                         |
| --------------------------- | -------------------------------------------------------------------- |
| `claude --continue`         | Resumes the most recent interactive session in the current directory |
| `claude --resume`           | Opens the session picker                                             |
| `claude --resume <name>`    | Resumes the named session directly                                   |
| `claude --from-pr <number>` | Opens the picker filtered to sessions linked to that pull request    |
| `/resume`                   | Switches to a different conversation from inside an active session   |

The exclusions matter more than the table suggests. Sessions created with `claude -p` or the Agent SDK are **left out of the picker and out of `claude --continue`** — you resume one by passing its session ID to `claude --resume <session-id>`. `claude --continue` also skips background sessions and sessions whose first prompt was `/loop`. But `claude -p --continue` **includes** `-p`, SDK and `/loop` sessions, and still skips background ones.

You can run `claude --resume <session-id>` from any directory. Claude Code looks in the current project directory and its git worktrees first, then in every other project on this machine.

### What a resumed session restores

A resumed session brings back the conversation **and some of the state saved in it**:

- **Conversation history** — the full history, including tool calls and results.
- **Model** — the session continues on the model it was using, unless that model has been retired or a `--model` flag or `ANTHROPIC_MODEL`-family variable picks one at launch.
- **Agent** — a session started with `--agent` continues as that agent, keeping its system prompt, tool restrictions and model.
- **Permission mode** — restored on the terminal paths, with real exceptions (below).
- **Active goal** — a goal still active when the session ended carries over; its turn count, timer and token baseline reset.
- **Scheduled tasks** — those that have not expired. Background Bash and monitor tasks are not restored.

What is **not** restored is the launch configuration. If the session depended on `--mcp-config`, `--settings`, `--plugin-dir`, `--fallback-model`, or directories added with `--add-dir`, pass them again when you resume. Directories added mid-session with `/add-dir` are not restored either. Settings files such as `settings.json` are re-read at launch, so anything living in them needs no repeating.

The permission-mode rules are the ones that catch people:

| Session ended in    | How you resume       | Permission mode after you resume                               |
| ------------------- | -------------------- | -------------------------------------------------------------- |
| `bypassPermissions` | Terminal             | The mode a new session would start in — never restored         |
| `plan`              | Terminal             | The mode a new session would start in                          |
| `auto`              | Terminal             | `auto`, if your account still meets the auto-mode requirements |
| Any mode            | Session picker       | Not restored — the mode a new session would start in           |
| Any mode            | `/resume` in-session | Not restored — the conversation continues in your current mode |

The short version: resuming a permissive session never hands you back its permissiveness for free.

### Naming a session so you can find it

| When                    | How to set the name                                             |
| ----------------------- | --------------------------------------------------------------- |
| At startup              | `claude -n auth-refactor`                                       |
| During a session        | `/rename auth-refactor` — the name also shows on the prompt bar |
| From the session picker | Highlight a session and press `Ctrl+R`                          |
| On plan accept          | Accepting a plan generates a title, unless you already named it |

If another live session on this machine already uses the name you pick, Claude Code leaves the name with the session that has it and renames yours to a variant with a two-word suffix, such as `auth-refactor-graceful-unicorn`, and tells you.

Sessions you never name still get two labels, and only one of them is a resume handle. The **default display name** — the working directory's name plus a two-character suffix, like `my-app-3f` — identifies the session in listings but **cannot be passed to `--resume`**. The **generated title**, a short summary of your first prompt written by a background request to a small fast model, can.

### The session picker

Run `/resume` inside a session, or `claude --resume` with no arguments. By default it shows sessions from the current worktree, including background ones marked `bg`, plus sessions started elsewhere that added the current directory with `/add-dir`.

| Shortcut  | Action                                                                |
| --------- | --------------------------------------------------------------------- |
| `↑` / `↓` | Navigate between sessions                                             |
| `→` / `←` | Expand or collapse grouped sessions                                   |
| `Enter`   | Resume the highlighted session                                        |
| `Space`   | Preview the session content                                           |
| `Ctrl+R`  | Rename the highlighted session                                        |
| `/`       | Enter search mode and filter; a pasted PR or MR URL finds its session |
| `Ctrl+A`  | Show sessions from all projects on this machine                       |
| `Ctrl+W`  | Show sessions from all worktrees of this repository                   |
| `Ctrl+B`  | Filter to sessions from the current git branch                        |
| `Esc`     | Exit the picker or search mode                                        |

### Branching and forking

Three things copy a conversation, and they differ in **where you end up**:

| You want                                                    | Use               | Where you end up                                     |
| ----------------------------------------------------------- | ----------------- | ---------------------------------------------------- |
| To try a different direction yourself, keeping the original | `/branch [name]`  | Switched into the copy; the original stays resumable |
| A copy to work in the background while you carry on here    | `/fork [prompt]`  | Still here; the copy runs as a background session    |
| A side task whose answer comes back into this conversation  | `/subtask <task>` | Still here; a subagent reports back                  |

`/branch` copies the transcript and switches the running process to write to it. The confirmation prints two session IDs — the branch you are now in, and the original, which is unchanged on disk. Because the branch runs in the same process, your "allow for this session" permission grants carry over; in-flight background subagents and Bash commands keep running and their output lands in the branch, and a connected Remote Control device follows you into it.

From the command line, the same idea is `--fork-session` combined with `--continue` or `--resume`: it creates a new session ID instead of reusing the original. Because that is a **separate process**, it starts without your existing session grants and you re-approve there.

### Sessions that started somewhere else

Two entry points bring a conversation in from another surface rather than from your own transcript store. `claude --teleport`, and the in-session `/teleport` (also `/tp`), pull a Claude Code on the web session into this terminal: a picker opens, then Claude Code fetches the branch and the conversation. It needs a claude.ai subscription. Going the other way, `/remote-control` (alias `/rc`) makes the session you are in available for Remote Control from claude.ai or the Claude app, so you can carry on from another device without moving the session anywhere.

### Asking an old session a question from a script

`/export` renders a transcript for a person. For a script, pass a session ID to `claude -p --resume`:

<CodeBlock title="ask a finished session for a summary">

```bash
claude -p --resume <session-id> --output-format json "summarize what we changed" | jq -r '.result'
```

</CodeBlock>

Here is this lesson's example prompt, the shape that makes a resumed session worth resuming:

```text
Pick up where we left off: the pagination fix is in, the test passes.
Next, do the same for the API handler and show me the diff before anything else.
```

Naming what is already done is what stops a resumed session from redoing it.

## Anti-patterns

**Expecting `claude --continue` to find a headless session.** It will not: `-p` and SDK sessions are excluded from `--continue` and from the picker. _Fix:_ keep the `session_id` from the JSON envelope and use `claude --resume <id>`, or use `claude -p --continue`.

**Resuming a `bypassPermissions` session and assuming it is still permissive.** It is not — that mode is never restored on resume. _Fix:_ pass the launch flag again, or set `permissions.defaultMode` in user or managed settings, if you genuinely want it.

**Trying to resume by the default display name.** `my-app-3f` identifies a session in listings but is not a resume handle; `--resume` will not find it. _Fix:_ name sessions you care about with `-n` or `/rename`, or resume by the generated title, which does work.

**Using `/branch` to protect your files.** Branching copies the conversation, not the working tree. Two branches editing the same repo still fight over the same files. _Fix:_ use a git worktree — `claude -w <name>` — when you want file isolation.

**Resuming the same session in two terminals.** Without forking, messages from both interleave into one transcript. _Fix:_ `--fork-session` on the second one.

**Parsing `~/.claude/projects/**/\*.jsonl`in a script.** The entry format is internal and changes between releases. _Fix:_ use`/export`, `--output-format json`, or `claude -p --resume` to ask the session itself.

<Callout variant="changed">
  `claude --resume <session-id>` now searches beyond the directory you are standing in: the current
  project and its git worktrees first, then every other project on this machine. Before v2.1.223 the
  lookup stopped at the current project directory, so you had to `cd` to wherever the session last
  ran.
</Callout>
