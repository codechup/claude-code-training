## Objectives & prerequisites

By the end of this lesson you can:

- List what loads into the context window before you type anything, and why a "fresh" session is never empty.
- Read `/context` and act on it.
- Choose correctly between `/compact`, `/compact <instructions>`, `/autocompact <tokens>`, `/clear` and a subagent.
- Predict what survives an automatic compaction and what is summarised away.
- Recognise the two failure patterns a full context window produces: the kitchen-sink session and repeated failed corrections.

**Prerequisites.** Lesson `05-checkpoints-rewind` (the rewind menu's summarize options are part of this toolkit).

<WhenNotToUse>
  Do not compact reflexively. Compaction replaces messages with a summary, and detailed instructions
  from early in the conversation can be lost in the process — sometimes the right move is to let
  context accumulate because you are deep in one problem and the history *is* the work. Do not
  `/clear` mid-task either: it resets the whole window, so anything not written down in `CLAUDE.md`,
  a plan file or a commit is gone. And `/context` is a diagnostic, not a habit; run it when
  something surprises you or before a long task, not after every turn.
</WhenNotToUse>

## Concept

### A session is never empty

Before your first keystroke, the window already holds the system prompt, your project's `CLAUDE.md`, auto memory (the first 200 lines or 25 KB of `MEMORY.md`, whichever comes first), environment info, MCP tool names and skill descriptions. Then the session fills further: every file read, every command's output, every path-scoped rule that loads alongside a matching file.

That is why the best-practices guide puts one constraint above all others: **"Claude's context window fills up fast, and performance degrades as it fills."** As the window gets full, Claude starts losing earlier instructions and making more mistakes. Persistent rules belong in `CLAUDE.md`, not in conversation history — that is the practical consequence, and it is the subject of the next module.

### The four commands

<CodeBlock title="context commands">

```text
/context              # live breakdown by category, with optimisation suggestions
/context all          # the fuller view

/compact              # summarise the conversation now
/compact focus on the auth bug fix     # summarise, keeping what you name

/autocompact 500k     # set how full the window gets before auto-compaction runs

/clear                # reset the context window entirely

/memory               # open and edit the CLAUDE.md and memory files /context lists
```

</CodeBlock>

`/context` also tells you which `CLAUDE.md` and auto-memory files actually loaded — the fastest way to answer "why is it behaving like that?" when a session surprises you.

`/compact` with instructions is strictly better than `/compact` alone when you know what matters next: the summary keeps what you choose instead of what the automatic pass guesses. `/clear` is for switching to unrelated work; the guide's advice is to use it _frequently_ between tasks.

There is a fifth lever from the previous lesson: `/rewind` → **Summarize from here** / **Summarize up to here** compresses only part of the conversation. Use it when the middle of the session is the noisy part.

### What survives compaction

Compaction is not uniform. It matters which mechanism loaded a piece of context:

| Mechanism                                   | After compaction                                                      |
| ------------------------------------------- | --------------------------------------------------------------------- |
| System prompt and output style              | Unchanged — not part of message history                               |
| Project-root `CLAUDE.md` and unscoped rules | Re-injected from disk                                                 |
| Auto memory                                 | Re-injected from disk                                                 |
| The plan Claude wrote in plan mode          | Re-injected from disk                                                 |
| Rules with `paths:` frontmatter             | Reloaded as Claude reads files they match                             |
| Nested `CLAUDE.md` in subdirectories        | Reloaded as Claude reads files in that subdirectory                   |
| Files Claude read or edited                 | Claude Code re-reads up to five, most recently modified first         |
| Invoked skill bodies                        | Re-injected, capped at 5,000 tokens per skill and 25,000 tokens total |
| Context that hooks added earlier            | Summarised with the rest of the conversation                          |

Read that table once and the reason for the standard advice becomes obvious. A rule in `CLAUDE.md` comes back after every compaction; the same rule typed into the chat does not. A file over 5,000 tokens comes back after compaction as a path reference rather than its contents, shown as `Referenced file` instead of `Read`.

### When the window fills up

Claude Code compacts automatically as you approach the limit, so a full window does not end your session. It clears older tool outputs first, then summarises the conversation if needed. Your requests and key code snippets are preserved; detailed instructions from early in the conversation may not be.

Four ways to act before the automatic pass decides for you: compact with a focus, compact part of the conversation from the rewind menu, run `/autocompact <tokens>` to move the trigger point earlier, or delegate a large read to a subagent so the file contents land in _its_ context window instead of yours.

If a single file or tool output is so large that context refills immediately after each summary, Claude Code stops auto-compacting after a few attempts and shows an error rather than looping.

If you need a bigger window rather than a smaller conversation, Fable 5.1, Fable 5, Sonnet 5, Opus 4.6 and later, and Sonnet 4.6 support a 1 million token context window — that is level 2's topic.

## Anti-patterns

**The kitchen-sink session.** One task, then an unrelated question, then back to the first task — the window is now full of things neither task needs. _Fix:_ `/clear` between unrelated tasks.

**Correcting over and over.** After two failed corrections the context holds two failed approaches, and the third correction competes with them. _Fix:_ `/clear` and write one better prompt that incorporates what you learned.

**Putting standing rules in the chat.** Conversation history is summarised at compaction; `CLAUDE.md` is re-injected from disk. A rule you typed in message three may simply be gone by message ninety. _Fix:_ put persistent rules in `CLAUDE.md` (module `m03-memory`).

**Unscoped investigation.** "Investigate the auth system" with no boundary reads hundreds of files into your window before any work starts. _Fix:_ scope it, or delegate it to a subagent whose reads stay in its own context.

**`/clear` when you meant `/compact`.** `/clear` is a reset, not a compression; anything not on disk is gone. _Fix:_ `/compact <instructions>` mid-task; `/clear` only when switching tasks.
