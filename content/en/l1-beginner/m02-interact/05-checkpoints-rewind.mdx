## Objectives & prerequisites

By the end of this lesson you can:

- Say when a checkpoint is created and how many a session keeps.
- Open the rewind menu two ways — `/rewind`, or `Esc` twice with an empty prompt input — and choose the right one of its six options.
- List the four categories of change checkpointing does **not** restore, and name the tool that covers each gap.
- Use "Summarize from here" / "Summarize up to here" as a targeted `/compact`.
- Undo a Claude edit without the TUI, from a headless or scripted run.

**Prerequisites.** Lesson `02-tools-read-edit-run` (checkpoints track file-editing tools, so you need to know which those are), and a clone of the lab repository.

<WhenNotToUse>
  Checkpoints are session-level recovery, not version control — the docs say so in as many words.
  They do not cover anything a Bash command touched, they do not cover edits made by most subagents,
  and their file snapshots are deleted in the retention sweep roughly 30 days after the session last
  saved one. If the change matters beyond this afternoon, commit it. If you are about to try
  something genuinely risky in a repository with uncommitted work, commit or stash **first** and use
  git as the safety net; use `/rewind` for the ordinary "that turn went wrong" case it was built
  for.
</WhenNotToUse>

## Concept

### What gets checkpointed, and when

- **Every user prompt creates a new checkpoint.** Not every edit — every prompt.
- Claude Code snapshots the files its editing tools are about to change, before the change.
- A session keeps file snapshots for the **100 most recent** checkpoints.
- Checkpoints are saved with the conversation, so `/rewind` still works after you resume a session.
- Snapshots are removed in the retention sweep, by default about 30 days after the session last saved one. Rewinding to a checkpoint whose snapshots are gone can fail with `No files were restored`. Raise `cleanupPeriodDays` to keep them longer.

### The rewind menu

<CodeBlock title="opening the rewind menu">

```text
/rewind                 # run the command, from anywhere in the session
Esc Esc                 # press Escape twice while the prompt input is EMPTY
```

</CodeBlock>

If the prompt input contains text, a double `Esc` clears it instead of opening the menu — the cleared text goes to your input history, so press `Up` to get it back after you are done in the menu.

The menu lists each prompt you sent this session. Pick a point, then pick an action:

| Option                            | What it does                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------- |
| **Restore code and conversation** | Revert both to that point                                                    |
| **Restore conversation**          | Rewind the conversation, keep the current code                               |
| **Restore code**                  | Revert file changes, keep the conversation                                   |
| **Summarize from here**           | Compress the conversation from this point _forward_ into a summary           |
| **Summarize up to here**          | Compress the conversation _before_ this point, keeping later messages intact |
| **Never mind**                    | Return to the list without changing anything                                 |

The two code-restore options appear **only** when the selected checkpoint has tracked file changes to revert. After restoring the conversation or choosing "Summarize from here", the original prompt from the selected message is put back into the input field so you can re-send or edit it.

To guide a summary, highlight a **Summarize** option with the arrow keys and type instructions where the row reads _add context (optional)_, then press `Enter`. Selecting the option with its number key summarises immediately, with no instructions. Summarising does not change files on disk, and the original messages stay in the session transcript.

If you ran `/clear` earlier in the same Claude Code process, the rewind menu gains an entry at the top of the list labelled `/resume <session-id> (previous session)` — select it to get back to the conversation that was active before `/clear`. That entry requires Claude Code v2.1.191 or later; on earlier versions run `/resume` and pick the previous session from the list.

### The four gaps

This is the part to memorise, because each gap has a different answer:

| Not restored                        | Why                                                                                     | What covers it                                            |
| ----------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Files changed by **Bash commands**  | Only direct edits through Claude's file-editing tools are tracked                       | git                                                       |
| Edits by most **subagents**         | A background fork, a `/code-review --fix` run — those edits are not in your checkpoints | git. (A _foreground_ forked skill's edits are restored)   |
| **External changes**                | Manual edits and other concurrent sessions are not captured                             | git                                                       |
| **Symlinked and hard-linked paths** | A restore skips them and warns `Restored the code, but skipped N files`                 | Edit the file yourself, or ask Claude to reverse the edit |

Anything that reaches a remote system — a database write, an API call, a deployment — cannot be checkpointed at all. That is what permission modes and permission rules are for.

### Working without the menu

Two undo paths need no TUI at all, and both are worth having in your fingers:

- **Ask.** "Undo that" is a normal instruction; Claude reverses its own edit with the same tools it used to make it.
- **git.** `git diff` to see what changed, `git checkout -- <path>` to throw it away. This is the only path that covers a change a Bash command made.

## Anti-patterns

**Treating `/rewind` as version control.** Checkpoints are session-scoped, capped at 100, and swept after ~30 days. _Fix:_ commit anything you would be upset to lose; use `/rewind` for the current session's mistakes.

**Assuming a Bash-made change is recoverable.** `mv`, `rm`, `sed -i` and a script that rewrites files are all invisible to checkpointing. _Fix:_ commit before letting a session run file-mutating shell commands.

**Double-`Esc` with text in the input.** It clears the input instead of opening the menu, which reads like a bug the first time. _Fix:_ clear the input first, or just run `/rewind`; your cleared text is in the input history under `Up`.

**Rewinding code and forgetting the conversation.** "Restore code" leaves the conversation believing the edit exists, so the next turn builds on a file state that is gone. _Fix:_ pick "Restore code and conversation" unless you specifically want the history.

**Expecting a subagent's edits back.** A background fork or a `/code-review --fix` run edits your tree, and rewinding does not restore those. _Fix:_ use git; only a _foreground_ forked skill's edits are covered.

  Requires Claude Code v2.1.191 or later; on earlier versions you had to run `/resume` and pick the

</Callout>
