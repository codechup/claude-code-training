## Objectives & prerequisites

By the end of this lesson you can:

- Say why `ultracode` is a Claude Code setting rather than a model effort level, and what it turns on beyond `xhigh` reasoning.
- Name every route that turns it on, and the one environment variable that silently disables its orchestration half.
- Predict whether the `ultracode` keyword fires for a given prompt — including the routes where it deliberately does not.
- Choose a size guideline and say what agent count each value aims for.
- State what the docs actually claim about workflow cost, and what they do not claim.

**Prerequisites.** Lesson `01-workflows` (the Workflow tool and its script), and effort levels from L2 `m05-models-effort`.

<WhenNotToUse>
  `ultracode` plans a workflow for _every_ substantive task in the session, so each request uses
  more tokens and takes longer than at lower effort levels. That is the wrong trade for routine work
  — a small edit, a question about a file, a commit message — and for any session where you are
  watching cost closely, since ultracode sessions also switch off the large-run warning. It is
  unavailable on models without `xhigh` effort, and it is not a substitute for asking for a workflow
  once: if only one task in the session deserves orchestration, ask for that one task and leave the
  session at `high`.
</WhenNotToUse>

## Concept

### A setting, not an effort level

`/effort` offers `low`, `medium`, `high`, `xhigh` and `max` — model reasoning levels — and then
offers `ultracode`, which is something else. **Ultracode is a Claude Code setting**: it sends `xhigh`
to the model _and_ has Claude orchestrate dynamic workflows for substantive tasks. With it on, Claude
plans a workflow for each substantive task instead of waiting for you to ask, and a single request
can turn into several workflows in a row — one to understand the code, one to make the change, one
to verify it.

Every route that turns it on:

| Route                                                       | What it does                                                                                                        |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `/effort ultracode`                                         | Turns it on for the current session                                                                                 |
| `claude --effort ultracode`                                 | Starts the session at `xhigh` with ultracode on (2.1.203 or later)                                                  |
| `"ultracode": true` in a settings file, or via `--settings` | Persists it, so every session starts with it                                                                        |
| The `/model` picker's effort slider                         | Move it to `ultracode` with the arrow keys; on for the current session, even if you save that model as your default |
| Agent SDK                                                   | `applyFlagSettings()` accepts `effortLevel: "ultracode"`                                                            |

Two gaps are worth memorising. The persisted `effortLevel` setting and the
`CLAUDE_CODE_EFFORT_LEVEL` environment variable **do not accept `ultracode`** — that value has its
own `ultracode` settings key. And when `CLAUDE_CODE_EFFORT_LEVEL` is set to anything other than
`xhigh`, requests run at that level and ultracode's workflow orchestration stays inactive; selecting
ultracode then warns you that the variable overrides effort for the session. Where workflows are
turned off entirely, `--effort ultracode` sets `xhigh` effort only.

`/effort ultracode` lasts for the current session. Drop back with `/effort high` when you return to
routine work.

### The keyword, and where it does not fire

To run a single task as a workflow without changing the session's effort level, include the keyword
`ultracode` in your prompt — or ask in your own words, since Claude treats "use a workflow" as the
same opt-in:

```text
ultracode: audit every API endpoint under src/routes/ for missing auth checks
```

Claude Code highlights the keyword in your input. The keyword only chooses how Claude structures the
work: the agents' tool calls receive the same permission checks and sandboxing as any other tool call
in the session. If you did not mean it, press `Option+W` (macOS) or `Alt+W` (Windows and Linux) to
dismiss the highlight for this prompt, or backspace with the cursor right after the highlighted
keyword. To stop it triggering at all, turn off **Ultracode keyword trigger** in `/config`.

The keyword is an opt-in **only in a prompt you type yourself**: at the interactive prompt, in an IDE
extension panel, in a Remote Control client, or in an Agent SDK application that stamps your keyboard
input's `origin` as `{ kind: "human" }`. It does not start a workflow when it reaches the session
another way:

- a prompt passed with `-p`
- a prompt an Agent SDK application sends without stamping it as human input
- a scheduled task prompt
- a webhook payload or pull request comment relayed into the conversation

That last one is the security point, not a quirk: a keyword that anyone could put in a PR comment
would be a way to spend your tokens. The lab below is that rule, measured.

### Bounding the size

A **size guideline** tells Claude how many agents to aim for when it writes a workflow. Claude Code
sends it as advice, not a cap, so a prompt that calls for a different scale still overrides it
(2.1.202 or later):

| Value          | Agent count Claude aims for                         |
| -------------- | --------------------------------------------------- |
| `unrestricted` | No guideline: Claude sizes the workflow to the task |
| `small`        | Fewer than 5 agents                                 |
| `medium`       | Fewer than 15 agents                                |
| `large`        | Fewer than 50 agents                                |

The default is `medium` (2.1.219 or later; earlier versions defaulted to `unrestricted`). Set it in
the **Dynamic workflow size** row of `/config`, with `/config workflowSizeGuideline=small`, or with
the `workflowSizeGuideline` key in a settings file — the settings file wins, and Claude Code then
hides the `/config` row. Changes take effect on the next prompt, and the runtime's own caps still
apply regardless.

### What the docs say about cost

Be careful here: there is no published multiplier for ultracode, and you should not invent one. What
the official pages state is:

- A workflow spawns many agents, so a single run **can use meaningfully more tokens** than working
  through the same task in conversation. Runs count toward your plan's usage and rate limits like any
  other session.
- With ultracode on, **each request uses more tokens and takes longer** than at lower effort levels,
  and a single request can become several workflows in a row.
- Claude Code flags a run that grows unusually large: when a workflow schedules **more than 25
  agents**, or its projected token total passes **1.5 million**, the progress line shows a
  `Large workflow` warning pointing you at `/workflows`. The warning is advisory — it does not pause
  or limit the run. Choosing a size guideline replaces the 25-agent threshold with that guideline's
  count, and **sessions with ultracode on do not show the warning at all**, because turning it on
  already opts you in to large runs.
- The runtime's caps — 16 concurrent agents, 4,096 items per `parallel()`/`pipeline()` call, 1,000
  agents per run — bound the cost of a runaway script.
- For comparison, the costs page does give one number for the sibling feature: **agent teams use
  approximately 7× more tokens than standard sessions when teammates run in plan mode**. That is a
  figure about agent teams, not about workflows or ultracode.

The practical advice the docs give is the one to keep: **run the workflow on a small slice first** —
one directory instead of the whole repo, a narrow question instead of a broad one. The `/workflows`
view shows each agent's token usage as the run progresses, and you can stop the run there, usually
without losing completed work. Check `/model` before a large run if you usually switch to a smaller
model for routine work, and ask for a smaller model on stages that do not need the strongest one.

### Turning workflows off

Toggle **Dynamic workflows** off in `/config`, set `"disableWorkflows": true` in
`~/.claude/settings.json`, or set `CLAUDE_CODE_DISABLE_WORKFLOWS=1` (read at startup). For an
organisation, `"disableWorkflows": true` in managed settings, or the toggle on the Claude Code admin
settings page. When workflows are disabled the bundled workflow commands and the
`/workflow-authoring` skill are unavailable, the `ultracode` keyword no longer triggers a run, and
`ultracode` disappears from the `/effort` menu.

## Anti-patterns

**Putting `ultracode` in a scripted prompt and expecting orchestration.** In `-p`, in an SDK message
without a human `origin`, in a scheduled task and in a relayed webhook or PR comment, the keyword is
plain text. _Fix:_ in automation, ask for the `Workflow` tool explicitly and allow it — the keyword is
a human's opt-in, not an API.

**Leaving ultracode on all session.** It plans a workflow for every substantive task, including the
ones that needed one delegated read. _Fix:_ `/effort high` for routine work; use the keyword for the
one task that deserves a workflow.

**Setting `CLAUDE_CODE_EFFORT_LEVEL` and then selecting ultracode.** Unless the variable is `xhigh`,
requests run at the variable's level and the orchestration half stays inactive. _Fix:_ unset the
variable, or use the `ultracode` settings key.

**Quoting a cost multiplier for ultracode.** The docs give thresholds and caps, not a factor; the
only published multiple — roughly 7× — is for agent teams whose teammates run in plan mode. _Fix:_
measure your own run from the `/workflows` view or the JSON envelope's `total_cost_usd`, and quote
that.

**Treating the `Large workflow` warning as a limit.** It is advisory, it does not pause anything, and
it does not appear at all when ultracode is on. _Fix:_ set a size guideline, and stop runs yourself
from `/workflows`.

<Callout variant="changed">
  `--effort ultracode` requires Claude Code 2.1.203 or later; before that the flag printed `Unknown
  --effort value 'ultracode'` and the session started at the default effort. And since 2.1.210 the
  keyword no longer starts a workflow from a `-p` prompt, an unattributed SDK message, a scheduled
  task or a relayed webhook or PR comment — before that version, it did.
</Callout>
