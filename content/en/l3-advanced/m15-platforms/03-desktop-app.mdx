## Objectives & prerequisites

By the end of this lesson you can:

- Open the Desktop app's **Code** tab, pick an environment (Local, Cloud, SSH or WSL) and start a session.
- Run several sessions in parallel, each in its own git worktree, and say where those worktrees live.
- Arrange the diff, terminal, file and Browser panes, and use the Browser pane to preview a running app.
- Create a **local** scheduled task, choose its schedule, and explain the three cases where it will not run.
- Say which of the three scheduling surfaces — cloud routines, Desktop tasks, `/loop` — fits a given job.
- Describe what the iOS Simulator pane does on macOS and why it is not computer use.

**Prerequisites.** A Pro, Max, Team or Enterprise subscription. On Windows, Git for Windows must be installed and the app restarted afterwards, or local sessions will not work. Lessons `01-vs-code` and `02-jetbrains` first, so you can compare surfaces.

<WhenNotToUse>
  Desktop trades CLI-only features for visual review, so it is the wrong choice when you need to
  script Claude Code or use the Agent SDK, when you want agent teams (a CLI feature; Desktop has
  dynamic workflows instead), or when you want inline autocomplete-style code suggestions, which
  Desktop does not provide. It connects to Anthropic's API by default: running the Code tab on
  Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry or a self-hosted gateway is
  possible, but it is a separate "Claude Desktop on 3P" setup rather than something you configure in
  the app. Local scheduled tasks are the wrong tool for anything that must run when your machine is
  off or asleep: use a cloud routine instead. And the iOS Simulator pane is macOS-only and
  local-session-only — a cloud or SSH session runs on a machine that cannot reach the simulators on
  your Mac.
</WhenNotToUse>

## Concept

### Three tabs, one of them ours

The Claude Desktop app has three tabs: **Chat** (conversation, no file access), **Cowork** (an autonomous background agent in a sandboxed VM), and **Code** (the coding assistant with direct access to your local files). Everything in this lesson is the **Code** tab.

Desktop _includes_ Claude Code — you do not need Node.js or a separate CLI install for it. If you also want to type `claude` in a terminal, install the CLI separately. Desktop and the CLI run the same engine, can run simultaneously on the same project, and share configuration: `CLAUDE.md` files, MCP servers, hooks, skills and settings.

### Starting a session

Pick an environment first:

| Environment | Where the code runs                                                                            |
| ----------- | ---------------------------------------------------------------------------------------------- |
| **Local**   | Your machine, on your files directly. Windows needs Git installed.                             |
| **Cloud**   | The same infrastructure as Claude Code on the web; continues if you close the app.             |
| **SSH**     | A remote machine. Desktop installs Claude Code there automatically on first connect.           |
| **WSL**     | Windows only — inside a WSL 2 distribution, with Claude Code, tools and git on the Linux side. |

Then a model from the dropdown next to the send button, then a permission mode: **Auto** (a classifier reviews actions in the background and blocks the risky ones), **Manual** (approve each change), **Accept edits** (edits auto-applied), **Plan** (propose without editing).

### Parallel sessions and worktrees

**+ New session** (`Cmd+N` / `Ctrl+N`) starts another one. For git repositories **each session gets its own isolated copy of the project using git worktrees**, so changes in one do not affect another until you commit. `Ctrl+Tab` / `Ctrl+Shift+Tab` cycle sessions; holding `Cmd` / `Ctrl` while clicking a sidebar session opens it in a second pane alongside the current one.

Worktrees live in `<project-root>/.claude/worktrees/` by default — changeable in **Settings → Claude Code → "Worktree location"**, along with a branch prefix for every worktree branch. To include gitignored files like `.env`, add a `.worktreeinclude` file to your project root.

### Panes

The Code tab is a drag-and-drop layout of panes: chat, diff, browser, terminal, file, plan, tasks, subagent, plus the iOS Simulator on macOS. Drag by the header to move, drag an edge to resize, `Cmd+\` / `Ctrl+\` to close the focused pane, **Views** in the session toolbar to open more.

- **Terminal** (Ctrl and the backtick key, on both platforms) opens in the session's working directory and shares Claude's environment, so `npm test` sees the same files Claude is editing. Local sessions only.
- **File** pane: click a path in the chat or diff to open it, make spot edits, **Save**. Local and SSH sessions only; for cloud sessions, ask Claude to make the change.
- **Browser** pane: run your dev server and the app opens here. Claude can view the running app, test endpoints, inspect logs and iterate on what it sees. It can also open external sites.
- **Diff** pane: a `+12 -1` indicator appears after edits; click it to review file by file and comment on specific lines. Claude reads your comments and revises. **Review code** has Claude evaluate its own diffs and leave inline suggestions.

The keyboard shortcut sheet is `Cmd+/` / `Ctrl+/`. Note that terminal interactive-mode shortcuts (`Shift+Tab` to cycle permission modes, for instance) **do not apply in Desktop**.

### The iOS Simulator pane (macOS)

When Claude builds, installs, launches or checks your app in a simulator, the **iOS Simulator** pane opens automatically and streams the device screen live. It drives the simulator directly, so — and this is the part people get wrong — **it does not need computer use and never takes over your screen**. From the CLI, Claude reaches the simulator through computer use instead, which does control your screen.

It is in public beta on macOS on Pro, Max, Team and Enterprise (except Enterprise organisations with a HIPAA configuration), needs Claude Desktop v1.24012.0 or later and Xcode 26.x with the iOS platform installed, and works in local sessions only. Each device belongs to the session that launched it, up to 4 panes per session. The first time Claude uses a device you are asked to allow it, once per device. Screenshots of the device are sent to Anthropic under your normal retention settings — so do not sign in to real accounts on a device Claude uses.

### Scheduled tasks

Desktop's **Routines** page creates two different things. A **local scheduled task** runs on your machine with access to your files and tools, but only fires while the app is open and the computer is awake. A **remote routine** runs in the cloud even when your computer is off, and can also fire on API calls or GitHub events. Pick deliberately:

|                       | Cloud routine                       | Desktop task          | `/loop`               |
| :-------------------- | :---------------------------------- | :-------------------- | :-------------------- |
| Runs on               | Cloud, Anthropic-managed by default | Your machine          | Your machine          |
| Requires machine on   | No                                  | Yes                   | Yes                   |
| Requires open session | No                                  | No                    | Yes                   |
| Access to local files | No (fresh clone)                    | Yes                   | Yes                   |
| Permission prompts    | No (runs autonomously)              | Configurable per task | Inherits from session |
| Minimum interval      | 1 hour                              | 1 minute              | 1 minute              |

To create one: in the **Code** tab click **Routines**, then **New routine**, then **Local**. Fill in Name (lowercased to kebab-case and used as the folder name on disk), Description, Instructions (with pickers for permission mode and model, plus the working folder and an isolated-worktree toggle), and Schedule. A folder is required before you can save, and Desktop asks you to trust it first. Schedule presets are **Manual**, **Hourly**, **Daily**, **Weekdays** and **Weekly**; for anything else — every 15 minutes, the first of the month, a single future run — just ask Claude in any Desktop session.

That is this lesson's worked example prompt, and it is a real feature, not a figure of speech:

```text
Set up a local scheduled task that runs every weekday at 9am, reviews the
commits pushed to this repo since the previous weekday, and writes a short
summary. Run it in an isolated worktree.
```

Three things about how they run, all of which bite eventually:

- **Timing drift.** Desktop checks every minute while the app is open and adds a small deterministic delay of a few minutes to stagger API traffic.
- **Skipped runs.** If the computer sleeps through a scheduled time, the run is skipped. **Keep computer awake** under **Settings → Desktop app → General** prevents idle sleep; closing the lid still sleeps.
- **Catch-up runs.** On app start or wake, Desktop starts exactly one catch-up run for the most recently missed time in the last seven days and discards anything older. So a 9am task can run at 11pm. Write guardrails into the prompt: _"Only review today's commits. If it's after 5pm, skip the review and just post a summary of what was missed."_

Permissions are per task. Allow rules from `~/.claude/settings.json` also apply. A Manual-mode task that needs an unapproved tool **stalls until you approve it**, with the session waiting in the sidebar. The practical fix is to click **Run now** after creating the task, watch for prompts, and choose "always allow" for each. MCP tools marked `requiresUserInteraction` prompt every call and offer no always-allow, so those runs stall each time.

Each task's prompt lives at `~/.claude/scheduled-tasks/<task-name>/SKILL.md` (or under `CLAUDE_CONFIG_DIR`), with YAML frontmatter for `name` and `description` and the prompt as the body; edits take effect on the next run. Schedule, folder, model and enabled state are _not_ in that file. A running task can even reschedule itself with the `update_scheduled_task` MCP tool.

### Moving work off Desktop

**Continue in** (the VS Code icon in the session toolbar) sends a session to **Claude Code on the Web** — Desktop pushes your branch, summarises the conversation and creates a cloud session with the full context; this requires a clean working tree and is not available for SSH sessions — or opens the project in **Your IDE**. Selecting **Cloud** instead of **Local** at session start does the same for work you know up front will be long.

**Dispatch** goes the other way: you message a task from the Claude mobile app, and Dispatch decides how to handle it. Development-shaped tasks spawn a Code session in Desktop's sidebar with a **Dispatch** badge, and you get a push notification when it finishes or needs approval. Dispatch requires a Pro or Max plan and is not available on Team or Enterprise.

## Anti-patterns

**Using a local scheduled task for something that must happen.** It fires only while the app is open and the machine is awake, and a missed day collapses into a single catch-up run. _Fix:_ use a cloud routine for anything that must run reliably; keep Desktop tasks for work that genuinely needs local files.

**Writing a scheduled prompt with no sense of time.** "Review today's commits" run at 11pm as a catch-up is a different job than it was at 9am. _Fix:_ put the guardrail in the prompt — what to do if it is late, what window to look at.

**Leaving a Manual-mode task to run unattended.** It stalls on the first unapproved tool and sits there. _Fix:_ **Run now** once, approve with "always allow", and check the task's **Always allowed** panel afterwards.

**Assuming terminal shortcuts work.** `Shift+Tab` does not cycle permission modes in Desktop. _Fix:_ `Cmd+/` / `Ctrl+/` for the real list; `Cmd+Shift+M` opens the permission-mode menu.

**Expecting the iOS Simulator pane in a cloud or SSH session.** Local sessions on macOS only — the remote machine cannot reach your Mac's simulators. _Fix:_ run those sessions locally.

**Signing into real accounts on a simulator Claude drives.** Its screenshots go to Anthropic under your normal retention settings. _Fix:_ use test accounts.
