## Objectives & prerequisites

By the end of this lesson you can:

- Install the Claude Code extension in VS Code and open it from the Spark icon, the Activity Bar, the Command Palette or the Status Bar.
- Send a prompt with your current selection attached, and add an explicit `@file.ts#5-10` reference with `Option+K` / `Alt+K`.
- Review a proposed edit in VS Code's side-by-side diff and accept, reject, or edit the proposal before accepting.
- Say what the extension gives you that `claude` in the integrated terminal does not — and what the terminal still gives you that the extension does not.
- Connect an _external_ terminal session to a running VS Code window with `/ide`, and know which flag does it at launch.

**Prerequisites.** VS Code 1.94.0 or higher; a paid Claude subscription (Pro, Max, Team or Enterprise) or a Claude Console account — no API key required. You need a git checkout of the lab repository (`lesson/m15-01-start`). The earlier modules on permission modes (`m04`) and git workflows (`m08`) are assumed.

<WhenNotToUse>
  Skip the extension when you are working over SSH on a box with no editor, when you are scripting
  Claude Code (`claude -p`, the Agent SDK and every headless workflow are CLI-only), or when you
  need a CLI-only feature the extension does not carry. It is also the wrong surface for a task you
  will not watch: a long autonomous refactor belongs in a cloud session or a background session, not
  in a panel you have to keep focused. And if your editor is a VS Code fork the extension will not
  install into, install the CLI and run `claude` in that editor's integrated terminal instead — the
  CLI works in any terminal.
</WhenNotToUse>

## Concept

### Same engine, different window

The extension is not a different product. It runs the same agentic loop, reads the same `CLAUDE.md`, honours the same settings and connects to the same MCP servers as the CLI. What changes is the interface: instead of a scrolling transcript you get a panel that lives inside your editor, VS Code's own diff viewer for every proposed edit, and your editor's selection handed to Claude automatically.

One nuance worth knowing before you install: **the extension bundles its own copy of the CLI for the chat panel.** If you also want to type `claude` in VS Code's integrated terminal, you need the standalone CLI install as well.

### Opening it

Throughout VS Code, the **Spark icon** means Claude Code. Four ways in:

| Entry point     | How                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Editor Toolbar  | Click the Spark icon in the top-right of the editor. Appears only when a file is open.          |
| Activity Bar    | Click the Spark icon in the left sidebar to open the sessions list. Always visible.             |
| Command Palette | `Cmd+Shift+P` / `Ctrl+Shift+P`, type "Claude Code", pick an option such as **Open in New Tab**. |
| Status Bar      | Click **✱ Claude Code** at the bottom right — available when `preferredLocation` is `sidebar`.  |

The first time you open the panel, sign in through the browser. If you later see **Not logged in · Please run /login**, the extension reopens the sign-in screen by itself; if it does not, run **Developer: Reload Window**.

### Selection context and `@`-mentions

Claude automatically sees your selected text. That is the default, with no keystroke. Pressing `Option+K` (macOS) / `Alt+K` (Windows, Linux) goes one step further and inserts an explicit reference such as `@file.ts#5-10` into your prompt, so the range is written into the conversation rather than being implicit context for one turn.

Both paths flow through the same mechanism: while the extension is connected, the CLI includes your current editor selection and the active file's path as context on each prompt. To keep a sensitive file such as `.env` out of that, add a `Read` **deny** rule for its path — a matching deny rule blocks both the selected text and the open-file notice.

This lesson's worked example prompt is deliberately shaped around a selection, because that is the one thing the extension does that a bare terminal cannot:

```text
Explain what the lines I have selected do, then tell me the one edge case
they do not handle. Do not change any files yet.
```

### Reviewing changes

What you see when Claude wants to edit depends on the permission mode shown at the bottom of the prompt box:

- **Auto** — a classifier reviews most actions instead of asking you. On Pro, Max and Team plans this is the extension's built-in starting mode.
- **Manual** — Claude shows a side-by-side comparison of the original and the proposal, then asks. You accept, reject, or say what to do instead. **If you edit the proposed content in the diff view before accepting, Claude is told that you modified it**, so it does not carry on assuming the file matches its own proposal.
- **Plan** — Claude describes the approach first. VS Code opens the plan as a full Markdown document you can annotate inline before Claude begins.
- **Edit automatically** — edits land without asking.

### The `ide` MCP server

When the extension is active it runs a local MCP server named `ide` that the CLI connects to. This is how diffs open in the native viewer, how selections reach `@`-mentions, how Claude reads editor diagnostics, and — in a Jupyter notebook — how it asks VS Code to execute cells. It is hidden from `/mcp` because there is nothing to configure, but it exists, and it matters if your organisation allowlists MCP tools in a `PreToolUse` hook.

The server hosts about a dozen tools; the rest are internal RPC the CLI uses for its own UI and are filtered out before the tool list reaches Claude. **Two** reach the model:

| Tool                       | What it does                                                 | Read-only |
| -------------------------- | ------------------------------------------------------------ | --------- |
| `mcp__ide__getDiagnostics` | Returns the errors and warnings in VS Code's Problems panel. | Yes       |
| `mcp__ide__executeCode`    | Runs Python in the active Jupyter notebook's kernel.         | No        |

`mcp__ide__executeCode` cannot run anything silently: the code is inserted as a new cell at the end of the active notebook and a native Quick Pick asks you to **Execute** or **Cancel** on every call. Cancelling, or dismissing with `Esc`, returns an error to Claude and nothing runs. That Quick Pick is separate from `PreToolUse` hooks — an allowlist entry lets Claude _propose_ a cell; the Quick Pick is what lets it _actually_ run. The JetBrains plugin is different here, and the next lesson says how.

### Extension or CLI?

Everything in the extension is also in the CLI. The reverse is not true, and the split is worth memorising:

| Want                                                  | Use                                        |
| ----------------------------------------------------- | ------------------------------------------ |
| Inline diffs, plan review as a document, session tabs | Extension                                  |
| `claude -p`, the Agent SDK, any script                | CLI                                        |
| An external terminal driving your open VS Code window | CLI plus `/ide` (or launch `claude --ide`) |
| Browser automation                                    | Either — see `06-chrome`                   |

## Anti-patterns

**Pasting the file into the prompt because "the extension can't see it".** It can. Your selection is attached automatically, and `@`-mentions cover everything else. Pasting large content into VS Code's integrated terminal is worse than useless: it can drop characters before they reach Claude Code. _Fix:_ select, or `@`-mention, or ask Claude to read the file.

**Installing the extension and expecting `claude` in the terminal.** The extension bundles a CLI copy for its own panel only. _Fix:_ install the standalone CLI too if you want the terminal command.

**Leaving `.env` visible.** Selection and open-file context reach Claude on every prompt while the extension is connected. _Fix:_ add a `Read` deny rule for the path; that blocks both the selected text and the open-file notice.

**Accepting a diff you did not read because Auto mode "already checked it".** Auto mode's classifier blocks risky actions; it does not judge whether the change is what you wanted. _Fix:_ read the diff, and use Manual mode on anything you would not merge unreviewed.

**Assuming the extension can do headless work.** Scripting, the Agent SDK, `claude -p` in CI: all CLI-only. _Fix:_ keep the CLI installed for automation and use the extension for interactive work.
