## Objectives & prerequisites

By the end of this lesson you can:

- Install `claude-agent-sdk` into a virtual environment with either `uv` or `pip`.
- Write the same read-only review agent in Python, and map every option name to its TypeScript twin.
- Handle messages with the SDK's typed classes (`SystemMessage`, `AssistantMessage`, `ResultMessage`) instead of string comparisons.
- Recognise the two platform problems that show up on Windows and fix both.
- Decide, for a given job, which of the two SDKs you should reach for.

**Prerequisites.** Python 3.10 or later (this lesson was verified on 3.12.10), and lesson 05 — the concepts are identical, so this lesson spends its time on what is different.

<WhenNotToUse>
  Everything from lesson 05 applies here: if you only need one answer, `claude -p` is simpler than a
  dependency, and a hosted agent with a managed sandbox is a different product. The Python-specific
  boundary is the runtime: `query()` is an async generator, so it needs an event loop. Dropping it
  into a synchronous framework — a plain WSGI view, a Celery task, a notebook cell that is not
  async-aware — means wrapping it in `asyncio.run()` per call and paying full agent startup each
  time. If your host is synchronous and latency matters, run the CLI as a subprocess instead.
</WhenNotToUse>

## Concept

### Same SDK, snake_case

The Python and TypeScript SDKs are the same product. `query()` is still the entry point, still returns an async iterator, and still yields one message per step of the loop. The differences are naming and typing:

| TypeScript                     | Python                                  |
| ------------------------------ | --------------------------------------- |
| `query({ prompt, options })`   | `query(prompt=..., options=...)`        |
| `options: { … }`               | `options=ClaudeAgentOptions(…)`         |
| `allowedTools`                 | `allowed_tools`                         |
| `permissionMode`               | `permission_mode`                       |
| `maxTurns`                     | `max_turns`                             |
| `settingSources`               | `setting_sources`                       |
| `cwd`                          | `cwd`                                   |
| `message.type === 'assistant'` | `isinstance(message, AssistantMessage)` |

The Python side gives you real classes to match on, which is nicer than string comparison: `SystemMessage`, `AssistantMessage`, `ResultMessage`. The one wrinkle is that `SystemMessage` carries its payload in a `data` dict, so the `init` event's model and cwd come out as `message.data.get('model')` and `message.data.get('cwd')` rather than attributes.

The worked example prompt is deliberately identical to lesson 05's, so you can compare the two runs line by line:

```text
Read BUGS.md and src/store.ts. Name the one function that holds the off-by-one
pagination bug, and quote the single line that is wrong. Do not edit anything.
```

### Installing

Two supported paths. `uv init` then `uv add claude-agent-sdk` handles the virtual environment for you. Or do it by hand: `python3 -m venv .venv` and `source .venv/bin/activate` on macOS or Linux, `py -m venv .venv` and `.venv\Scripts\Activate.ps1` on Windows, then `pip install claude-agent-sdk`.

If PowerShell blocks `Activate.ps1` with an execution-policy error, `Set-ExecutionPolicy -Scope Process RemoteSigned` clears it for that shell only.

The SDK bundles a native Claude Code binary, with one documented exception: if pip installs the source distribution instead of a platform wheel — on ARM64 Windows, for example — there is no bundled binary, and you install Claude Code natively instead. The SDK then finds it on your `PATH`.

### Authentication and settings

Identical to lesson 05, because it is the same engine underneath. `ANTHROPIC_API_KEY` is read from the process environment, `.env` files are not loaded for you, and the third-party provider switches are the same environment variables. `setting_sources=[]` gives you the same isolation mode, with the same limits: no `settings.json` from `~/.claude` or `.claude/`, no `CLAUDE.md` — but managed policy, the global `~/.claude.json` and auto memory under `~/.claude/projects/<project>/memory/` still load, so pair it with `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` when that matters too. One version caveat the TypeScript side does not have: Python SDK 0.1.59 and earlier treated an empty list the same as omitting the option, so isolation silently did nothing. This lesson was verified on 0.2.152.

### Which SDK for which job

Neither is more capable. Pick by where the agent has to live: the language your surrounding application is written in, and the ecosystem you need alongside the agent — a web framework, a data pipeline, a notebook. If you have a genuine choice, the deciding question is usually whether the rest of the system is already async.

<CodeBlock title="agent.py">

```python
import asyncio
import os

from claude_agent_sdk import (
    AssistantMessage,
    ClaudeAgentOptions,
    ResultMessage,
    SystemMessage,
    query,
)

LAB = os.environ["LAB_DIR"]


async def main():
    async for message in query(
        prompt=(
            "Read BUGS.md and src/store.ts. Name the one function that holds the "
            "off-by-one pagination bug, and quote the single line that is wrong. "
            "Do not edit anything."
        ),
        options=ClaudeAgentOptions(
            cwd=LAB,
            allowed_tools=["Read", "Glob", "Grep"],
            permission_mode="dontAsk",
            max_turns=8,
            model="sonnet",
            setting_sources=[],  # no settings.json or CLAUDE.md (auto memory still loads)
        ),
    ):
        if isinstance(message, SystemMessage) and message.subtype == "init":
            print(f"init: model={message.data.get('model')} cwd={message.data.get('cwd')}")
        elif isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)
                elif hasattr(block, "name"):
                    print(f"Tool: {block.name}")
        elif isinstance(message, ResultMessage):
            print(f"Done: {message.subtype} (turns={message.num_turns})")


asyncio.run(main())
```

</CodeBlock>

Two things about that run are worth stopping on.

**Two SDKs, one agent.** Put this transcript next to lesson 05's: both agents read the same two files, reach the same conclusion about `paginate()`, and both volunteer that the checked-out tag already carries the fixed line. Nothing about the reasoning is language-specific, because the loop is the same engine in both cases. What differs is the wording — the model is not deterministic, and treating two runs as byte-identical is a test you will lose.

**`asyncio.run(main())` is not decoration.** `query()` is an async generator, so `async for` needs a running event loop. That single line is the whole reason the "When not to use this" section warns about synchronous hosts.

## Anti-patterns

**Calling `query()` without an event loop.** It is an async generator; a bare `for` over it raises. _Fix:_ put the loop in an `async def` and call it with `asyncio.run()`, or `await` it from an already-async host.

**Installing into the system Python.** The SDK pulls in a sizeable dependency tree, and mixing it into a global interpreter is how version conflicts start. _Fix:_ `uv` or a `venv`, always.

**Assuming a wheel was installed.** On a platform with no wheel, pip falls back to the source distribution and no Claude Code binary is bundled. _Fix:_ if the SDK cannot find a binary, install Claude Code natively — the SDK picks it up from `PATH`.

**Matching on strings instead of types.** `message["type"] == "assistant"` throws away everything the Python SDK gives you. _Fix:_ `isinstance(message, AssistantMessage)`, and remember `SystemMessage` keeps its payload in `.data`.

**Copying the TypeScript option names.** `allowedTools` is silently not `allowed_tools`. _Fix:_ build the options with `ClaudeAgentOptions(...)` so a wrong keyword is a `TypeError` at the call site rather than a silently ignored setting.

**Diffing two runs and calling a difference a regression.** The model is not deterministic; the wording changes. _Fix:_ assert on what you actually care about — the tools used, the exit status, a value you extracted — not on the prose.

<Callout variant="changed">
  The Python package is `claude-agent-sdk`, imported as `claude_agent_sdk`; it was renamed from
  `claude-code-sdk` / `claude_code_sdk`, and `ClaudeCodeOptions` became `ClaudeAgentOptions`. Two
  version notes matter: since v0.1.0 the SDK no longer applies Claude Code's system prompt by
  default, and Python SDK 0.1.59 and earlier treated `setting_sources=[]` the same as omitting it —
  upgrade before relying on isolation mode.
</Callout>
