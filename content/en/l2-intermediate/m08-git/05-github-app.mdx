## Objectives & prerequisites

By the end of this lesson you can:

- Say what `/install-github-app` installs, what secret it stores, and what it leaves you to merge.
- List the prerequisites it checks, and what it does when one is missing.
- Read the Claude GitHub App's permission table and explain why it is larger than the Claude Code GitHub Action needs.
- Choose between the quick setup, the manual setup, and a custom GitHub App.
- Distinguish the three products that share the "Claude Code" name on GitHub: the GitHub Action, managed Code Review, and Claude Code on the web.
- Uninstall the integration cleanly.

**Prerequisites.** Lessons 01–04, **admin access** to the repository you are connecting, and the [GitHub CLI](https://cli.github.com) installed and authenticated with `gh auth login`. Claude Code checks for `gh` and warns you if it is missing.

<WhenNotToUse>
  This is a change to a repository other people share, so it is the one lesson in this module you
  should not practise on someone else's project — including this course's lab repository. Skip the
  quick setup entirely when you do not run Claude Code locally, when you need full control of the
  workflow files, or when your organisation will not accept the app's full permission set: GitHub
  does not let you accept a subset, so the answer there is a custom GitHub App with only Contents,
  Issues and Pull requests. Skip it too when what you actually wanted was a review before you push —
  that is `/code-review` from lesson 04, and it needs no app at all.
</WhenNotToUse>

## Concept

### What the command does

Run `/install-github-app` inside `claude`, in the repository you want to connect, and follow the prompts. It performs four steps:

1. **Installs the Claude GitHub App** on the repository you pick.
2. **Sets up an authentication secret.** If Claude Code already has an API key it reuses that key, and offers to keep the repository's existing `ANTHROPIC_API_KEY` secret if one is set. Otherwise you choose between creating a long-lived token with your Claude subscription and pasting in an API key. It is saved as a repository secret — `ANTHROPIC_API_KEY` for an API key, `CLAUDE_CODE_OAUTH_TOKEN` for a subscription token.
3. **Pushes a branch** with the workflow files you select, already wired to that secret.
4. **Opens GitHub in your browser** with a pull request ready to create.

You create and merge that pull request. Then `@claude` works in the repository.

After the app is installed, Claude Code asks whether to continue with GitHub Actions setup. Choosing **Skip for now** stops with only the app installed; run `/install-github-app` again later to finish the workflow and secret steps.

### What you get

With the interactive workflow merged, mentioning `@claude` in an issue or pull request comment — or in the body or title of a newly opened issue — starts a run. Progress and results appear as a comment on the triggering issue or PR. This lesson's example prompt is the middle line: a question asked in a PR comment, answered in the same thread.

<CodeBlock title="what a trigger comment looks like">

```text
@claude implement this feature based on the issue description
@claude how should I implement user authentication for this endpoint?
@claude fix the TypeError in the user dashboard component
```

</CodeBlock>

If you also select the review workflow, Claude posts each review on the pull request itself — an inline comment on each issue it finds, or one summary comment when it finds none. It skips some pull requests, such as drafts.

Two checks run on the triggering actor before Claude starts, and the run fails if either rejects it. On issue and pull request events the triggering user must have **write access** to the repository. And on every event a **bot actor** is rejected unless you list it in `allowed_bots`, which keeps bots from triggering Claude in a loop.

### The permission set

The Claude GitHub App is shared by every Claude feature that integrates with GitHub, so its single permission set is larger than the Claude Code GitHub Action alone uses:

| Permission       | Access         |
| ---------------- | -------------- |
| Actions          | Read and write |
| Checks           | Read and write |
| Contents         | Read and write |
| Discussions      | Read and write |
| Issues           | Read and write |
| Members          | Read           |
| Metadata         | Read           |
| Pull requests    | Read and write |
| Repository hooks | Read and write |
| Statuses         | Read           |
| Workflows        | Read and write |

The Claude Code GitHub Action itself relies on three of them: **Contents** (modify repository files), **Issues** (respond to issues) and **Pull requests** (create PRs and push changes). The rest belong to other features sharing the app. When the app requests a permission it did not have before, GitHub prompts the account owner to approve it and the installation keeps its old permissions until they do.

### Quick setup versus manual setup

| Path         | Use it when                                                                                                    |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| Quick setup  | You run Claude Code locally and want the app, the secret and the workflow PR prepared for you                  |
| Manual setup | You do not run Claude Code locally, the command fails, or you want full control of the workflow files          |
| Custom app   | Your organisation will only grant Contents, Issues and Pull requests — covers the Action only, not Code Review |

Manual setup is three steps you do yourself: install the [Claude GitHub App](https://github.com/apps/claude), add an `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` secret, and copy `examples/claude.yml` from the action's repository into `.github/workflows/`. Generate a subscription token with `claude setup-token`.

Both paths configure one repository at a time. To roll out across an organisation, install the app once at the organisation level, store the secret as an organisation-level Actions secret, and add the workflow to each repository or call a reusable workflow. For a shared secret prefer an API key over an OAuth token, since an OAuth token is tied to the subscription of whoever ran `claude setup-token`.

### Three products, one name

This is where people get lost, so it is worth stating plainly:

| Product                    | What it is                                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Claude Code GitHub Actions | `anthropics/claude-code-action@v1`, configured with workflow files you own. `/install-github-app` sets this up |
| Code Review                | A managed service that reviews PRs with no workflow file — research preview, Team and Enterprise plans         |
| Claude Code on the web     | Claude Code sessions from a browser or phone                                                                   |

All three install the same GitHub App. Only the first is what `/install-github-app` writes workflow files for.

### Uninstalling

Undo each piece that applies: delete the workflows using `anthropics/claude-code-action` from `.github/workflows/` (quick setup writes `claude.yml`, and `claude-code-review.yml` if you selected the review workflow); delete the `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` secret from the repository and from organisation secrets; and uninstall the Claude GitHub App **only** if you do not use it for another Claude feature such as Code Review or web auto-fix. Deleting a secret does not invalidate the credential it held — retire an API key in the Console as well.

## Anti-patterns

**Running it on a repository you do not own.** The command installs an app and stores a secret. _Fix:_ check `viewerPermission` is `ADMIN` first, and never point it at a shared lab or fixture repository.

**Approving the permission set without reading it.** The app grants eleven permissions because it is shared by several Claude features, not because the Action needs them all. _Fix:_ read the table; if your organisation objects, create a custom app with Contents, Issues and Pull requests.

**Expecting CI to run on Claude's commits.** GitHub does not trigger workflows on commits made with the default `GITHUB_TOKEN`. _Fix:_ remove `github_token: ${{ secrets.GITHUB_TOKEN }}` so the action authenticates as the Claude GitHub App, or pass a custom app token.

**Committing the credential.** _Fix:_ it belongs in a repository or organisation secret, referenced as `${{ secrets.ANTHROPIC_API_KEY }}`.

**Uninstalling the app to turn off the Action.** If you also use Code Review or web auto-fix, removing the app breaks those too. _Fix:_ delete the workflow files; leave the app installed.
