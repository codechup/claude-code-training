## Objectives & prerequisites

By the end of this lesson you can:

- Say exactly what fast mode is and is not: same model, same quality, lower latency, higher price per token.
- Name the models it works on and the platforms it is unavailable on.
- Explain each way `/fast` can refuse, and what the refusal message tells you to fix.
- Say why enabling it at the start of a conversation costs less than enabling it later.
- Choose between fast mode and a lower effort level for a given kind of work.

**Prerequisites.** Lessons `01-model-family` and `03-effort-levels`. Fast mode is the third dial, and it interacts with both of the others.

<WhenNotToUse>
  Fast mode is for interactive work where you are waiting at the keyboard — rapid iteration, live
  debugging, a deadline. It is the wrong tool for long autonomous tasks, batch processing and CI/CD
  pipelines, and for anything cost-sensitive: you pay $10/$50 per MTok where standard Opus 5 is
  $5/$25, and on a subscription that spend comes out of usage credits rather than your plan's
  included usage. It is also unavailable on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft
  Foundry and Claude Platform on AWS. Fast mode is in research preview, so its pricing and
  availability may change.
</WhenNotToUse>

## Concept

### What it is

Fast mode is a high-speed configuration for Claude Opus that makes the model **up to 2.5× faster at a higher cost per token**. It is not a different model: it is Opus with a different API configuration that prioritises speed over cost efficiency, so you get identical quality and capabilities with faster responses.

It is supported on **Opus 5 and Opus 4.8**, and not on Sonnet, Haiku or other models. Opus 5 is the fast-mode default from Claude Code v2.1.219.

### What it costs

| Model    | Input (MTok) | Output (MTok) |
| -------- | ------------ | ------------- |
| Opus 5   | $10          | $50           |
| Opus 4.8 | $10          | $50           |

That is double the standard Opus 5 rate of $5 / $25 per MTok, and the fast-mode price is flat across the full 1M-token context window.

Where the spend appears depends on how you signed in — run `/status` to check. On Pro and Max, fast mode is paid from your usage credits, and **Settings > Usage** on claude.ai shows the month's usage-credit spend without breaking fast mode out separately. On Team and Enterprise, your organisation pays from its usage credits and `/usage` shows your own spend. On Claude Console, your organisation pays with the rest of its API usage, and the Usage and Cost pages can group by **Speed (Research Preview)** to separate it.

One line from the docs is worth reading twice: fast mode usage draws directly from usage credits, even if you have remaining usage on your plan.

### The one-time cost of turning it on

Enabling fast mode adds a request header that is part of the cache key. So the first request Claude Code sends with fast mode on reads the entire conversation history with **no cache hits** — and those uncached input tokens are billed at fast-mode rates.

The consequence is a rule you can act on: the deeper into a conversation you are when you enable it, the more that first turn costs. Enable fast mode at the start of a session, not in the middle of a long one. The cost applies once per conversation, so toggling it off and on again later does not repeat it.

### Fast mode versus a lower effort level

Both make responses arrive sooner, by opposite means:

| Setting            | Effect                                                                           |
| ------------------ | -------------------------------------------------------------------------------- |
| Fast mode          | Same model quality, lower latency, higher cost                                   |
| Lower effort level | Less thinking time, faster responses, potentially lower quality on complex tasks |

They combine: fast mode plus a lower effort level is the maximum-speed configuration for straightforward tasks. If your problem is that a task is intrinsically slow because it requires a lot of reasoning, lowering effort changes the answer and fast mode does not.

### When `/fast` refuses

`/fast` is a toggle that reports its state, and it has several distinct refusals. Each one names its own fix:

| Message                                                             | What it means                                                                                                                       |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `Fast mode requires usage credits · /usage-credits to turn them on` | Usage credits are off for your account                                                                                              |
| `Fast mode has been disabled by your organization`                  | An Owner has not enabled it for a Team or Enterprise organisation — or a gateway configuration is being read as a disabled response |
| `is not in your organization's allowed models`                      | The `availableModels` allowlist excludes the fast-mode Opus model                                                                   |
| `Fast mode unavailable during evaluation. Please purchase credits.` | A Console organisation on the free Evaluation plan                                                                                  |
| `Fast mode unavailable due to network connectivity issues`          | The availability check to `api.anthropic.com` failed; requests run at standard speed                                                |

The allowlist case has one exception worth knowing: a session already running on an allowed Opus model that supports fast mode gets fast mode enabled on the current model instead of being refused.

Behind an LLM gateway there is a wrinkle. Before offering fast mode, Claude Code checks availability with a request made **directly** to `api.anthropic.com` — the check does not follow `ANTHROPIC_BASE_URL`. On a network that routes Claude traffic through a gateway and blocks direct egress, the check fails even though inference works. `CLAUDE_CODE_SKIP_FAST_MODE_NETWORK_ERRORS=1` treats a failed check as available; `CLAUDE_CODE_SKIP_FAST_MODE_ORG_CHECK=1` skips the check entirely. To disable fast mode outright, set `CLAUDE_CODE_DISABLE_FAST_MODE=1`.

### Toggling, persistence, and rate limits

In the CLI, type `/fast` and press Tab to toggle, or set `"fastMode": true` in your user settings. When it turns on, you see `Fast mode ON` and a small `↯` icon next to the prompt; run `/fast` again at any time to check the state. If your current model does not support fast mode, turning fast mode on also switches your model to Opus. Turning it off leaves you on Opus — use `/model` to move.

By default, fast mode you turn on in an interactive session persists across sessions. Set `fastModePerSessionOptIn: true` in any settings file to make every session start with it off; the saved preference is kept, so removing the setting restores the persistent behaviour. Owners on Team or Enterprise plans can deploy that organisation-wide through server-managed settings.

Fast mode has its own rate-limit pool, shared across the supported Opus models. When you hit it, fast mode falls back to standard speed automatically, the `↯` icon turns grey, you keep working at standard speed and pricing, and fast mode re-enables when the cooldown expires.

This lesson's example prompt is the kind of work fast mode is actually for — short, interactive, and waiting on you:

```text
The dev server is throwing "Cannot read properties of undefined" on /tasks after my
last change. Reproduce it, tell me the line, and stop. I'm watching.
```

  "fastModePerSessionOptIn": true

To use fast mode in a non-interactive run, pass it at launch — `claude -p --settings '{"fastMode": true}'` — which applies it to that session only and does not save it as your default.

## Anti-patterns

**Turning fast mode on halfway through a long session.** The first request with the header on reads your whole conversation with no cache hits, billed at fast-mode rates — the deeper in you are, the more it costs. _Fix:_ enable it at the start of a session, or start a new one.

**Reaching for fast mode when the problem is depth.** Fast mode gives you the same answer sooner, not a better answer. If Claude is producing shallow work, you want a different model or a higher effort level. _Fix:_ diagnose latency versus quality before you spend.

**Using it for autonomous or CI work.** Nobody is waiting on a pipeline's latency, and the pipeline pays double per token. _Fix:_ standard mode for batch, CI/CD and long autonomous tasks.

**Assuming a refusal means "not available to me".** Five distinct refusals exist, and three of them are configuration you or an admin can change. _Fix:_ read the exact message and match it against the table above.

**Forgetting you are still on Opus after turning it off.** `/fast` off leaves the model where it put it. _Fix:_ `/model` back to whatever you meant to be on.
