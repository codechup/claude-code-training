## Objectives & prerequisites

By the end of this lesson you can:

- Read the `/usage` Session block, including the `Prompt cache (main)` line, and say what a miss means.
- Read `cache_read_input_tokens`, `cache_creation_input_tokens` and `cache_creation.ephemeral_*` out of a JSON envelope and infer the cache TTL you got.
- Explain why a long-running session's usage climbs even when you are barely typing.
- Say which billing model you are on and where the authoritative number lives.
- Apply the five habits that move a bill the most, and skip the ones that do not.

**Prerequisites.** Lessons `01`–`05` of this module. `m02-interact`'s `06-context-basics` helps, because most cost questions are really context questions.

<WhenNotToUse>
  Do not optimise cost before you have a number. On a Pro or Max subscription the session cost
  figure is a locally computed estimate for API users — your usage is included in your subscription,
  so the dollar figure is not what you are billed. Chasing it there wastes attention that belongs on
  the plan-usage bars instead. And do not micro-manage the cache: the biggest, most reliable savings
  come from keeping context small and picking your model and effort once, not from clever settings.
</WhenNotToUse>

## Concept

### `/usage`, and its aliases

`/usage` shows session cost, plan usage limits and activity stats. **`/cost` and `/stats` are aliases for it** — the same screen under three names. The Session block at the top looks like this. This is the illustrative sample printed in the official `costs.md` page, quoted so you know the shape to look for — it is **not** a capture from this course's sessions, which is why it names a model (`claude-sonnet-4-6`) that appears in none of this module's recordings:

<CodeBlock title="Sample from the official costs.md doc — not a capture">

```text
Total cost:            $0.55
Total duration (API):  6m 20s
Total duration (wall): 6h 33m 10s
Total code changes:    0 lines added, 0 lines removed
Usage by model:
   claude-sonnet-4-6:  1.2k input, 5.3k output, 940.0k cache read, 50.0k cache write ($0.55)
```

</CodeBlock>

Three things about that number. It is computed **locally**, from token counts at list price — the authoritative figure for billing is the Usage page in the Claude Console. It **resets on `/clear`**, so the next session's total starts at $0. And on Pro and Max it is explicitly not what you are billed: your usage is included in your subscription, and the same screen shows you plan usage bars, activity stats and a usage breakdown instead.

On a Pro, Max, Team or Enterprise plan, `/usage` also breaks down what counts against your plan limits: **attribution** (which skills, subagents, plugins and MCP servers your recent usage went to), **behaviour flags** (long context, cache misses — flagged when one accounts for 10% or more), and **loops** (the heaviest scheduled tasks). Press `d` or `w` to switch between the last 24 hours and the last 7 days. The figures are computed from local session history on this machine, so usage from other devices or claude.ai is not included.

### The prompt cache line

After the main conversation's first API response, `/usage` adds a `Prompt cache (main)` line. Again, the example below is the one printed in `costs.md`, not a session of ours:

<CodeBlock title="Sample from the official costs.md doc — not a capture">

```text
Prompt cache (main):   14 requests · 91% of input tokens from cache · 2 misses (last 6m 10s ago, 310.2k tokens re-cached) · 1 expected rebuild (compaction or tool-result clearing) · warm (1h TTL, last activity 40s ago)
```

</CodeBlock>

- **Misses** are requests that re-processed content the cache already held. Claude Code counts a request as a miss when it re-processed more than 5% and at least 2,000 tokens of what it could have read from cache. Where it can identify a cause, the line names it — for example `likely cause: tool definitions changed`.
- **Expected rebuilds** are the misses Claude Code caused itself, by compacting or by clearing old tool results.
- **Warm or cold** says whether the cached prefix is still inside its lifetime, and which TTL is in effect.

That line covers the main conversation only, not subagents, and `/clear` resets it with the rest of the Session block.

### Why caching is most of your bill

Claude Code re-sends the full context on every request: system prompt, project context, every prior message and tool result, plus your new message. Most of each request is identical to the one before it, and prompt caching is how the API avoids reprocessing the unchanged part.

The economics are stark. A cache **read** costs 10% of the standard input price — 2.5% on Fable 5.1 — while uncached input costs the full rate. Concretely, on Sonnet 5 that is $2 per MTok for fresh input against $0.20 per MTok for a cache hit; a 5-minute cache **write** is $2.50 per MTok and a 1-hour write is $4.

So the single most expensive thing you can do in a session is invalidate the cache repeatedly. The documented invalidators are: switching models, changing effort level, turning on fast mode, connecting or disconnecting an MCP server, enabling or disabling a plugin, denying an entire tool, compacting, accumulating many images, and upgrading Claude Code. The documented keepers include editing files in your repository, editing `CLAUDE.md` mid-session, changing output style or permission mode, invoking skills and commands, and rewinding.

The TTL matters too. On a Claude subscription, within your plan's included usage, the main conversation gets a **one-hour** TTL; on usage credits, an API key or a cloud provider it is **five minutes**. `promptCacheTtl` (or `CLAUDE_CODE_PROMPT_CACHE_TTL`) sets it yourself; each control takes `5m` or `1h`.

The cache is also scoped more narrowly than people expect: effectively to one machine and one directory, because the system prompt embeds the working directory, platform, shell and memory paths. **That includes worktrees of the same repository** — each worktree has its own working directory and therefore its own cache.

### Why a long session's usage climbs

The docs list the causes, and they are all worth recognising because none of them look like "I asked for something expensive":

- **Long context** — every request carries the whole conversation, so a one-line question in a session that has been open all day still draws usage for the whole thing.
- **Cache misses** — your first message after a break longer than the cache lifetime reprocesses your full context.
- **Scheduled tasks**, **cross-session messages** and **goal check-ins** — each fires on its own schedule and sends your full context, even while you are idle.
- **Agent teammates** — each active teammate keeps consuming tokens until it exits.
- **Compaction** — `/compact` reads the conversation it summarises, so compacting a large context is itself a large request. `/clear` costs nothing.

Background functionality — conversation summarisation for `--resume`, some command processing — is real but small: typically under $0.04 per session.

### The habits that actually move the number

From the cost doc, in rough order of leverage:

1. **Clear between tasks.** `/clear` when you switch to unrelated work; `/rename` first if you want to `/resume` later.
2. **Choose the right model.** Sonnet handles most coding tasks and costs less than Opus; reserve Opus for complex architectural decisions and multi-step reasoning. For simple subagent work, `model: haiku` in the subagent's configuration.
3. **Pick model and effort once, at the top.** Every mid-session change is a cache rebuild.
4. **Give compaction instructions.** `/compact Focus on code samples and API usage`, or a "Compact instructions" section in `CLAUDE.md`.
5. **Keep tool definitions lean.** MCP tool definitions are deferred by default, so only tool names and server instructions enter context until Claude uses a specific tool. Whether connecting or disconnecting a server invalidates the cache depends on that: deferred tools leave the prefix alone, tools loaded into the prefix do not. `/context` shows what is consuming space, and CLI tools like `gh` and `aws` cost no per-tool listing at all.

This lesson's example prompt is a cost-shaped one — asking for the work to be scoped before it is done:

```text
Before you change anything: list the files you would need to read to add pagination
to the /tasks endpoint, and estimate how much of the context window that is. Then stop.
```

Read the Sonnet envelope as a worked example. `input_tokens` is **12** — the only genuinely new input in the whole run. `cache_read_input_tokens` is **214,589** and `cache_creation_input_tokens` is **15,938**: a read-to-write ratio of about 13 to 1, which is what a healthy session looks like. A high read-to-creation ratio means caching is working well; creation staying high turn after turn means something in your prefix keeps changing.

The `cache_creation` split is the TTL evidence: all 15,938 written tokens sit under `ephemeral_1h_input_tokens`, with `ephemeral_5m_input_tokens` at zero. That is the one-hour TTL a Claude subscription gets for the main conversation while it is inside the plan's included usage. On usage credits, an API key or a cloud provider, the same run would report those tokens under the five-minute bucket instead.

Now compare the effort-lab run: **12** new input tokens, **205,380** read from cache, **12,639** written. Nearly the same shape on a different task in a different repository — which is the point. Across ordinary agentic work, the overwhelming majority of what you pay for input is cache reads, and your leverage is in not throwing that cache away.

```text
/usage          # session cost, plan bars, prompt cache line (aliases: /cost, /stats)
/context        # what is currently in the context window
/compact Focus on code samples and API usage
/clear          # reset the session and its cost counters; costs nothing
/rename         # name the session first if you want to /resume it later
/insights       # HTML report on how you work, written to ~/.claude/usage-data/
/usage-credits  # turn usage credits on, or request them from an admin
```

</CodeBlock>

## Anti-patterns

**Treating the session cost figure as your bill.** It is a local estimate at list price, and on Pro and Max your usage is included in the subscription anyway. _Fix:_ use the Console Usage page for billing, and the plan bars in `/usage` for "am I about to hit a limit".

**Compacting to save money.** `/compact` reads the whole conversation to summarise it, and the summary invalidates the cache. It is a context-management tool, not a cost-saving one. _Fix:_ `/clear` between unrelated tasks — it costs nothing.

**Switching model or effort mid-task "just to try".** Each switch reprocesses the entire conversation as uncached input, at full rate. _Fix:_ decide at the top of the session; compare across sessions, not within one.

**Leaving a session open all day.** Long context plus scheduled tasks, cross-session messages and goal check-ins all keep sending your full conversation while you do nothing. _Fix:_ `/clear` (or close and reopen) between work blocks, and check the `/usage` behaviour flags.

**Optimising the cache in a worktree-heavy workflow and expecting sharing.** Each worktree is its own working directory and therefore its own cache prefix. _Fix:_ expect a cold first turn per worktree, and do not treat that as a bug.
