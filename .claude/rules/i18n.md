# Turkish translation rules (D016, D018)

English is the source language. Turkish pages are translations of an English original, never
independent rewrites. If the English is wrong, fix the English first, then re-translate.

## What stays in English

Technical terms keep their English form rather than getting an invented Turkish equivalent:

> hook, skill, subagent, agent, plugin, prompt, commit, branch, worktree, pull request, merge,
> permission mode, plan mode, sandbox, token, context window, MCP server, marketplace, artifact,
> routine, workflow, checkpoint, transcript, effort, headless.

Also unchanged: command names and flags (`claude -p`, `/effort`, `--permission-mode`), file and
directory names (`CLAUDE.md`, `.claude/hooks/`), code blocks, terminal output, URLs, frontmatter
keys and values, product and model names (Claude Code, Fable 5.1, Opus 5, Sonnet 5, Haiku 4.5),
and error messages quoted verbatim.

Prose _around_ those terms is fully Turkish. Take Turkish suffixes on an English term with an
apostrophe and vowel harmony that follows how the word is **pronounced**:

- `hook'u`, `hook'lar`, `hook'ları` (not `hook'yu`)
- `skill'i`, `skill'ler`, `skill'lerin`
- `subagent'ı`, `commit'i`, `branch'i`, `worktree'yi`, `prompt'u`, `token'ı`
- `MCP server'ı`, `pull request'i`

## First use and the glossary

The **first** use of a kept English term in a page gets a short parenthetical explanation and a
link to the glossary anchor:

```mdx
Bir [hook](/tr/playbook/glossary/#hook) (Claude Code'un yaşam döngüsündeki belirli anlarda
otomatik çalışan bir komut) ekleyelim.
```

- Anchor = the lowercase English term, kebab-cased: `#hook`, `#subagent`, `#pull-request`.
- Later uses in the same page are plain text — link once per page, not once per paragraph.
- If the term has no glossary entry yet, add one to `content/tr/playbook/glossary.mdx` in the same
  change (one line: term, one-sentence Turkish explanation), and propose the EN twin entry in the
  plan's Handoff notes.

## Diacritics

Turkish diacritics are always correct and never "ASCII-fied": **ç ğ ı İ ö ş ü** and their capitals
**Ç Ğ I İ Ö Ş Ü**. Watch the dotted/dotless `i` pair in particular — `İstanbul`, `ışık`, `için`,
`İngilizce`. Never write `Turkce`, `icin`, `sunlar`. Quotation marks are `"…"`, and the decimal
separator in prose is a comma (`1,5 saniye`), while code stays exactly as written in English.

## Translation checklist

1. Frontmatter: translate `title`, `description` and free-text `tags`. Do **not** change `level`,
   `module`, `order`, `duration_min`, `difficulty`, `verified_version`, `sources[]` URLs or
   `lab.repo_tag` — those must stay identical to the EN twin (the content gate compares them).
2. Keep the file at the mirrored path: `content/tr/<level>/<module>/<same-NN-slug>.mdx`. Slugs are
   never translated — EN and TR share slugs so the language switcher works (D015).
3. Keep every heading, section and component in the same order as the EN source. The template order
   in `.claude/rules/content.md` §1 applies to the TR page too.
4. Translate `sources[].title` only when the source itself is Turkish; an English document keeps its
   English title.
5. Transcripts and code blocks are copied byte-for-byte. Translating a comment inside a transcript
   would make it a fabricated recording (D070) — do not.
6. Flip `draft: true` → `draft: false` only when the whole page is translated, not partially.
7. Run `npm run gate` (EN/TR parity + schema) before committing.

Use the `translator` agent (`/translate-lesson <path>`) rather than translating inline: it is
configured with these rules and `sonnet` (D046).
